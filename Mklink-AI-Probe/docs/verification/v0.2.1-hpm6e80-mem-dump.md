# HPM6E80 mem_dump qualification

Date: 2026-09-13. Development branch: `codex/v0.2.1-development`.
Status: four-profile short matrix completed; extended qualification in progress.

## Target and changes

The HPM6E80 hpm6e00evk SDK1.11.0 flash-XIP Debug fixture was rebuilt with
SEGGER Embedded Studio8.24, downloaded through the HPM ROM API, and verified
by full readback of37,328 bytes. The600 MHz target's1 ms counter advanced and
its known4 KiB noncacheable RAM pattern matched.

HPM6E80 shares the JTAG ID used by HPM5301. A successful clock acknowledgement
does not identify an exact part or prove wiring stability. SDK/CLI/MCP/Web now
use an honest qualification description; profile names and defaults are unchanged.
The associated21 profile/dispatch tests pass.

The probe adds the SDK-defined HPM6E80 AXI SRAM window to the existing bounded
memory fast path. MMIO/OTP remain excluded. The20 MHz GPIO input sample moves
after TCK CLEAR to fix a previous-bit capture: expected0x800041b7 was read as
0x0000836e. Batch failure diagnostics preserve raw status before cleanup.
4/10/30 MHz shift kernels are unchanged. No RAM-read retry was added.

## Short matrix

All28 cases passed after the analyzer wiring was reconnected. Each clock tested
fixed Flash4B, fixed RAM4B, changing RAM4B, contiguous RAM64B, RAM4KiB,
Flash4KiB and four noncontiguous32-bit variables. RAM4KiB ran15 seconds per
clock; the other cases ran5 seconds. Every static payload was compared with
known contents; dynamic floats had to remain finite, in range and changing.
CRC, complete-block order, error/drop flags and increasing probe timestamps were
checked. Rates exclude the first200 ms and include subsequent frame gaps.

The20 MHz setting is a nominal profile; the current repaired kernel measures
below20 MHz. Clock readback is a profile acknowledgement, not a frequency meter.
The compiled-RV32 functional model passed6,976 scans, and the SBA model passed
boundary, last-word, fallback and injected-fault checks. Neither model establishes
electrical margin.

## Preserved failures and limits

The original firmware passed4/10 MHz baselines but failed at20 MHz; its results
are not relabeled as passing. During a later wiring check, a10 MHz dynamic case
failed after190,488 samples with invalid raw SBA status. It was stopped; the
cause is not established. The subsequent rewired28-case matrix had no new
SBA/DMI/USB or payload errors. One earlier analyzer capture had no TCK edges,
and an idle capture contained no DMI scans; neither was used for clock results.

Extended20/30 MHz tests and CLI/MCP/Chrome acceptance are pending. HPM5301 has
not been retested with this changed20 MHz aperture; its previous firmware's
qualification remains separate. No other HPM device, ARM speed, RTT benchmark,
ordinary mem_read/mem_write throughput or permanent OTP write is qualified here.
