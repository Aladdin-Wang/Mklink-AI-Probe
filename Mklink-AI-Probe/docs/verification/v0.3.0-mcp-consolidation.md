# 0.3.0 MCP 依赖与任务适配收敛

日期：2026-10-03。承接架构复审 A6，基于 c99cf4b 继续开发；A6 仍是分步迁移。

## 第一批：依赖与任务客户端收敛

共享 MCP 不再为了标准输入输出隔离而导入旧独占服务器。原隔离实现移到中性模块
`mcp_stdio.py`，新旧入口复用同一实现；未重新实现协议、串口或流式转发。
旧模块说明也改为明确的迁移保留状态，避免继续声称它是 `mklink mcp` 的活动入口。

任务提交集中到 `RuntimeClient.start_job`，查询与任务 ID 校验集中到
`runtime.job_status`。MCP、SDK、普通 CLI 和 `runtime jobs` 都调用这一契约，
适配器不再拼装任务 URL。后端 RuntimeJobs 继续负责确认、参数检查、会话版本、
互斥和去重；没有新增执行器、重试或任务状态机。

共享 MCP 的清理改用 FastMCP 的服务生命周期，不再在每次 build_server 时注册
进程级 atexit 回调。正常结束服务时释放自己的会话，即使进程继续存在也不残留心跳；
断开失败记录日志并由原有 TTL 兜底，不关闭 GUI 下载器、不停止他人的采集。

## 旧工具与共享能力盘点

按工具注册统计（含共同注册模块），旧服务器 69 个工具，活动共享服务器现为 25 个工具。
共享工具中的 `gui_call`、`superwatch`、`systemview` 会覆盖多个能力，因此不能用
69−25 计算功能缺口，也不能以新入口不再导入旧模块为由删除全部旧工具。

| 旧工具 | 共享路径与差异 |
|---|---|
| ping、discover_probes、connect、disconnect、device_status | 同名工具；connect/disconnect 已变为共享附着/解除语义。 |
| detect_mcu_profile | 尚无共享 MCP 对应工具；工程检测需迁移配置准入。 |
| flash、erase_chip、reset | start_job + job_status；显式确认和请求 ID，结果保留，不重放。erase_sector 尚未迁移。 |
| get_power、set_power_on、reboot_probe | 尚未进入共享能力目录；供电及探针重枚举不能用普通路由别名替代。 |
| security_status、security_lock、security_unlock | 尚未迁移；必须保留具体目标、确认及破坏性语义。 |
| read_memory、write_memory | 同名共享工具，受后台采集互斥和 4096 字节限制。 |
| read_memory_regions、dump_memory、flush_memory、measure_dump_memory | 批量、流式、观测及吞吐契约尚未迁移；不能拆成任意循环后宣称等价。 |
| configuration_script、configuration_description、read_configuration | 尚未迁移；前两类是配方生成/说明，后者会访问目标，应分别处理。 |
| peripheral_targets、select_peripherals、list_peripherals、capture_peripherals | MCP 对应流程尚未迁移；共享 register_snapshot 可读取已选目录，不等价于目录选择/连续采样。 |
| read_variable、write_variable、read_register | 同名共享工具；类型化实时写另走 superwatch_write。 |
| halt、resume、step | gui_call 同名能力。 |
| set_breakpoint、clear_breakpoint、clear_all_breakpoints | gui_call('breakpoints', {'action': ...})；当前共享实现仅覆盖已验证的 FPBv1。 |
| read_core_registers | gui_call('core_registers')；返回结构需适配，不能只改名字。 |
| load_symbols、symbols_status、memory_map | 状态/地图走 symbol_status、memory_map；改符号目前由 GUI 显式执行，遵守 A5 会话/采集准入。 |
| rtt_start、rtt_write、rtt_stop | 同名共享工具；订阅与停止要求所有权，参数/返回结构有变化。 |
| rtt_read、capture_rtt | rtt_history 是已有采集缓存；有限时长采集与捕获结果尚未等价迁移。 |
| systemview_start、systemview_read、systemview_stop、capture_systemview | systemview(action=...) 可启动/订阅/查历史/停止；私有定时读取、捕获契约仍有差异。 |
| systemview_analyze_events、systemview_decode | 同名离线工具；新旧入口共同注册，复用原分析器/解码器，无需连接或选择下载器。 |
| systemview_analyze、systemview_report、systemview_integrate | 定时采集分析、采集报告和工程集成尚未迁移；不能以离线工具替代后宣称语义等价。 |
| check_hardfault、decode_hardfault | fault_snapshot 与 hardfault 已有对应基础，但暂停、采样和输出结构不同，不建立隐式别名。 |
| modbus_open、modbus_close、modbus_read、modbus_write、modbus_scan | 共享目录目前仅 modbus_status；独立串口的操作/确认/资源归属仍需迁移。 |
| serial_list、serial_open、serial_close、serial_send、serial_read | 共享目录目前仅 serial_status；独立端口不能套用目标 CDC 的独占规则。 |
| set_debug_speed | 同名共享工具复用后台路由，持续采集期间拒绝；成功后保存工程配置。gui_call('debug_speed') 读取后台缓存档位。 |

共享入口另有 set_probe_alias、search_symbols、runtime_status、SuperWatch 适配和任务
查询，不能视为旧工具的简单子集。旧 mcp_stream_bridge 目前仍服务旧实现及其专属测试；
活动共享 MCP 使用后台 StreamHub/历史缓存，不启动该 sidecar。

`remote/capabilities.py` 的参数名、风险标记和远程协议仍独立；本轮没有机械合并到
本地 HTTP 能力表。后续应先建立操作级契约，再保留各传输的编码和确认适配。

## 第一批验证与边界

定向回归首批 69 项通过，扩大到新旧 MCP、观测、共享 SDK/CLI/任务/身份及远程包装
相关测试后 **333 通过、2 跳过**。验证包含：活动入口不导入旧服务器/sidecar，
诊断文本不污染 JSON-RPC，异常退出恢复 stdout，生命周期只解除自己的会话，
任务确认与旧会话约束、未知结果不重放、CLI 只轮询、断开后查询及非法任务 ID 拒绝。
旧流式 sidecar 的 websockets 弃用提示仍存在，没有以本次依赖解除掩盖它。

真实 Edge、主 V4 下载器与 STM32F103RET6 验证通过：

1. GUI 运行 RTT，MCP 订阅且 SDK 保持连接；MCP 提交已确认的 reset 仍被采集互斥拒绝。
2. 不调用 disconnect，直接正常结束 MCP stdio 子进程；8 秒观察窗口内仅该 AI 会话
   消失，SDK 与 GUI RTT 保持。截图已复核，无 pageerror/HTTP 5xx。
3. 显式停止 RTT 后，SDK 提交一次 reset。CLI 使用同一请求 ID 得到原任务，未新增
   任务；CLI 和未附着目标的另一个 MCP 都查询到相同的成功记录。
4. Boot 前 20 KiB 逐字节不变；复位后 VTOR 为 0x08005000，tick 推进。未烧录、
   擦除、修改下载器固件或 VCC。第二只下载器本轮只重新枚举，测试后台全部退出。

首轮进程退出断言失败是测试前提错误：FastMCP StdioTransport 默认 keep_alive=True，
退出 Client 上下文仍保留进程和会话。独立 EOF 实验确认正常清理有效，测试改用
keep_alive=False 后完整通过；没有为此增加产品补丁。强制杀进程仍需 TTL 兜底。

本轮没有修改 GUI，浏览器使用上一轮已验证的生产资源；未重跑 GUI 全量或 NSIS。
Python 全量、GUI 777 项及生产构建为上一轮证据，见符号重载报告，不能写成本轮执行。
所有私有脚本、日志、截图与设备标识仅保存在忽略的 .build。

本轮没有删除旧独占实现及其未迁移工具，未改变插件入口或安装版。新 MCP 不再依赖旧
服务器是依赖收敛，不等于旧模式的全部代码已经移除。后续继续按上表迁移，再删除
失去调用者的实现和专属测试；不为兼容旧名称重新开放直接串口访问。

稳定锁目录、bfcache、共享契约 CI 和双设备长稳继续排在后续；WebGUI 先于 NSIS。

## 第二批：离线工具与调试速度（基于 9bd1eb3）

`systemview_decode`、`systemview_analyze_events` 从旧服务器抽到 `mcp_analysis.py`，
新旧入口调用同一注册函数，原函数签名、输出及解码/分析算法保持一致。
这两项工具无需 RuntimeClient、目标连接或下载器选择，不创建独占读者；
共享入口调用后仍不导入旧服务器和 sidecar。

新增 `set_debug_speed` MCP 薄适配和 `debug_speed` / `set_debug_speed` 两项共享能力。
直接复用既有 REST 路由、profile_clock 校验、固件档位确认、成功后保存配置和
RuntimeGate 采集互斥。没有新增锁、状态机、重试或另一套参数校验。
档位作用于同一探针的所有客户端；GET 读取后台记录值，并非独立测量。
定时采集分析/报告、工程集成仍待迁移，本轮不改变这些工具的原始语义。

验证结果：

- 首批定向 **115 项通过**；扩大到新旧 MCP、共享 SDK/CLI/任务、真实 API 路由、
  探针控制及观测后 **244 项通过、1 跳过**，旧 sidecar 仍有 websockets 弃用提示。
  扩大验证第一次命令误用了不存在的测试文件名，没有执行测试；修正后通过。
- 交接/Skill 边界另 **57 项通过**；通过 MCP tools/list 核对旧入口 69 项、共享入口 25 项。
- 新旧 MCP 均在无需连接时完成已知字节解码、非法十六进制拒绝、空事件处理和
  overflow 后连续片段分析。覆盖共享改速不抢停采集、失败只执行一次、参数拒绝、
  固件失败不保存配置、操作锁释放，以及原 REST 路由同样受采集互斥约束。
- 真实 Edge + MCP stdio + SDK + 主 V4/F103：两只下载器同时在场，离线工具未 connect
  即可运行；GUI RTT 持续采集时改速被拒绝，缓存档位可读、RTT 保持。
- GUI 显式停止 RTT 后，MCP 设置 4 MHz，SDK 读取一致，目标 tick 推进；随后恢复
  原来的 30 MHz，MCP 仍附着时 GUI 可再次启停 RTT。此短测不代表所有板卡时钟认证。
- Boot 前 20 KiB 逐字节不变、VTOR 保持 0x08005000，未复位、烧录、擦除或改变 VCC。
  第二只只枚举，测试后台已退出；无 pageerror/HTTP 5xx，截图已检查。

GUI 源码未变，使用前轮生产资源；本轮没有重跑 GUI 全量/生产构建或 NSIS。
SystemView 离线测试使用已知输入，不代表真机 RTOS 事件采集验收。
私有日志、脚本及截图仅保存在忽略的 .build。当前仍是开发阶段，未合并或发布。

## 第三批：debug-speed CLI 迁移（基于 b7ec706）

专用 debug-speed CLI 原先仍调用 Device.connect，自行打开 CDC，并在 CLI 进程写
当前工作目录的配置。现加入既有 runtime_cli，共享命令增至 19 类。删除直接连接/
本地保存分支，增加 --probe 选择；未指定工程时采用选定后台的工程，显式冲突仍拒绝。

复用已有 set_debug_speed 能力和 REST 路由，未新增执行器或资源锁。路由增加严格
布尔 save（默认 true）并返回 saved。GUI/MCP 原先的成功后保存行为保持；CLI 明确
传入 --save 对应布尔值。不带该选项只改变当前后台连接的速度，CLI 退出不会还原；
带该选项才在成功后保存后台工程。内部参数名为 persist_profile，避免与内存读取的
--save 下载器文件参数混用。失效保存值在硬件操作前拒绝，失败不重试。

3 项迁移/校验用例修改前失败；修复后相关定向 **133 项通过**。共享工作流纳入实际
后台 API 文件，覆盖临时/持久配置及既有路由行为，同集 **208 项通过**。没有把假
客户端的 CLI 参数转发测试当成后台保存语义验证。

真实 Edge、CLI 子进程、MCP stdio、SDK 与主 V4/F103：

- GUI RTT 运行时 CLI 调速返回冲突，工程文件不变，GUI/AI/SDK 保持。
- 显式停止后，CLI 临时设置 4 MHz，配置逐字节不变，SDK/MCP 看到同一速度。
- CLI --save 设置 10 MHz，后台工程记录 medium，SDK 状态一致；CLI 退出不遗留会话。
- 恢复原 30 MHz，工程配置恢复原内容；MCP 仍附着时 GUI 可再次启停 RTT。
- Boot 前 20KiB 不变、VTOR 为 0x08005000、tick 推进，无复位/烧录/擦除/VCC 变化。
  第二只仅重新枚举，后台退出，无 pageerror/HTTP 5xx，截图检查通过。

GUI 未改，沿用前轮生产资源；本轮没有 NSIS 或长稳验收。其余专用 CLI、旧 MCP
未迁移能力和独立 Agent 仍需继续收敛，不能因这一项迁移而删除尚有用途的整个旧模块。
