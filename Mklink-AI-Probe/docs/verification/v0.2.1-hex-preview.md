# Online HEX preview and collapsed offline configuration

Date: 2026-09-14. Development branch: `codex/v0.2.1-development`.

## Defects and changes

- Offline option-byte/OTP configuration and erase/security controls now use two independent, initially closed disclosure sections. Expanding either section retains the existing controls and state.
- The old 262,144 Intel HEX record limit rejected large resource images. The parser now supports up to 4,194,304 records and coalesces adjacent records while decoding, avoiding millions of temporary chunk objects for contiguous data. File size (256 MiB), decoded data (64 MiB), checksum, address, overlap and segment limits remain enforced.
- Online inspection separates parsing from Flash coverage validation. A valid but out-of-range image remains readable in the preview and carries a coverage warning. It is not registered as an executable image/target pairing; the server rejects attempts to start a job with it.
- Without a selected chip, a custom FLM can be imported and its FlashDevice region used for preview coverage. Such algorithms have a separate preview scope. This does not infer target RAM, CPU or a programming context, and does not enable programming without an exact supported target.
- The GUI can clear a persisted target selection. A browser upload-copy input supplements the tracked file picker; uploaded copies do not follow subsequent changes to the source file.
