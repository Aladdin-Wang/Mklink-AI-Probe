# 0.3.0 第五阶段：共享寄存器、故障快照与断点

日期：2026-10-03。分支：`codex/v0.3.0-shared-runtime`，接续第四阶段 `622bc98`。
继续主机端迁移，不修改下载器固件、WinUSB、测试工程或正式安装版。

## 结果

- `read-reg`、`hardfault`、`break` 接入共享后台，删除对应旧直连实现。已迁移 CLI
  共 18 类；同一探针的 GUI、MCP、CLI、SDK 共用连接与操作准入。
- 新增 `register_snapshot`、`fault_snapshot`、`breakpoints` 三个能力，MCP 通过
  `gui_call`、SDK 通过 `call` 调用。REST 实现在独立 debug_api 模块，操作在工作
  线程执行，并持有同一目标租约；采集、独占任务或已有硬件请求期间拒绝冲突。
- 寄存器保留格式化输出、32 位及批量读取，最多 1024 项。已选外设目录时沿用
  目录的可读限制和字段解码；`--raw` 输出解码后的十六进制字节，不含 CDC 回显。
- CLI HardFault 使用不暂停目标的快照，仅显式 `--sp` 时读取 32 字节异常帧，
  通过后台 AXF 定位。架构故障寄存器不依赖 SVD 是否包含 SCB。短读失败不会
  被当作“无故障”。原 GUI 详细故障诊断的暂停行为不变。
- 断点目前限定 Cortex-M FPBv1。验证动作、地址及槽位，拒绝覆盖已占用槽位；
  自动分配只选择空闲槽位。设置/清除后读回校验，失败不重放。修正上半字指令
  地址显示，并读取完整比较器数量字段。函数使用后台 AXF，归一化 Thumb 标记。
- 断点是目标的共享状态，不属于某个客户端；CLI/AI 退出不清除断点。显式清除
  影响所有客户端，`--clear` 无参数仍表示全部清除。break 输出 JSON。
- 后台协议升为 6，旧开发后台需显式退出。公开操作说明已更新。

结束该测试会话，调整脚本使用目录中可读的 RCC 寄存器并验证拒绝路径，完整重跑

第二只下载器仅做连接、状态和磁盘身份查询，未修改目标 RAM/Flash 或执行状态。

固件、截图和日志只留在忽略目录，未提交。

## 边界与下一步

这次是运行中只读故障快照验收，未人为制造 HardFault，显式栈帧及符号解析主要由
单元测试覆盖。一个租约只能防止客户端交错，不能保证运行目标的多次读取原子性。
FPBv2、其他架构及断点命中后复杂单步行为不在本阶段新增支持范围。

后续继续 dump/watch/分析等专用 CLI、低层 Device 调用方及独立 Agent 的迁移；
完善全新连接的擦除算法准备、脱机部署，再进行操作中拔插/休眠、NSIS 安装升级、
日志轮转与至少 24 小时双设备长稳。保留 Bootloader+App 布局，App 起点仍是
0x08005000。现有双设备验证不能替代拔插或长稳验收；本分支仍是草稿，未合并或发布。
