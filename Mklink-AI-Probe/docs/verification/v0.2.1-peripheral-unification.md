# 0.2.1 外设读取三端统一

日期：2026-09-11。开发分支：`codex/v0.2.1-development`。
本记录针对源码服务，不代表正式安装包、发布或全部 ARM/HPM 板卡验收。

## 修复内容

- CLI `peripherals`、MCP 目录/字段/采集工具、Device SDK 和 Web 共用目录选择、解析、过滤与位提取。
- 持久化项目所选型号；Web 重连恢复目录。精确 PDSC 映射替代递归搜索第一个 SVD；多 Pack 同名型号必须指定 ID。
- `read-reg` 和 MCP `read_register` 支持字段名；SuperWatch CLI 使用与 Web 相同的位解码器，修复读取 GPIO 位时按整个整数解释的问题。
- 补齐 SVD 外设/cluster/寄存器/字段继承、数组展开、字母索引、bitRange，限制 XML、展开规模、递归和循环继承。
- 明确拒绝无安全可读项的目录、越界/不对齐地址、不完整快照、读取副作用和不支持的窄寄存器访问。
- 换芯片后不再残留旧 SVD 定义，也不回退到其他芯片的内置寄存器。
- 有限采集只用 dump_memory：最多 15 个寄存器区域、30 秒、100000 行，拒绝重复通道与无有效样本。

## 实板与浏览器

目标 HPM5301，已有目标程序持续改变 GPIO 输出、UART GPR 的低 8 位和 GPTMR1 计数器。
本轮无需改变探针固件或重刷目标程序。CLI、MCP、Web 依次独占探针。

| 入口 | 配置 | 有效样本 | 实测速率 | 结果 |
| --- | --- | ---: | ---: | --- |
| CLI subprocess | 3 通道 / 3 秒 / 1 ms | 2711 | 999.999 Hz | GPIO 0/1；UART 字段在 0..255；计数器变化 |
| 实际 MCP stdio 子进程 | 同上 | 2668 | 999.999 Hz | 目录、单次字段读取、连续采集、断开通过 |
| Chrome / WebSocket / 页面 Worker | 3 通道 / 1 ms | 浏览器收到 3201 | 后端 998.059 Hz | 三通道变化、页面零 JS 错误、GPIO 方波截图检查通过 |

三端 CRC 错误、协议丢帧、固件丢样标记均为零。Web 读取错误和传输丢弃为零。
启流解析器各丢弃了 74 字节命令回显；不宣称从首字节起绝对无损。
有效采样窗口短于请求墙钟时长，包含启流延迟，以上 Hz 按设备样本时间戳计算。
本次测量证明 1 kHz 场景可用，没有重新测量最高可用频率。

用户浏览器控制桥报 `nodeRepl.fetch request failed`；改用本机独立 Chrome 实例运行真实生产页面，
连接同一源码服务与真实硬件，没有模拟 HTTP、WebSocket 或 Worker 数据。
先验证 CLI 保存的型号能在新 Web 会话恢复，再通过页面重新选择型号、切到所有外设、选择通道、开始/停止并检查曲线。
最终 Web 回归还验证了 UART 字段快照和拒绝不属于 HPM 目录的 SCB 名称。
本地原始日志、脚本、采样和截图放在忽略目录 `.build/reports/peripheral-unification`，不提交 Pack/固件或设备标识。

## ARM 审计与边界

- 检查了协作固件项目中 `cmd_read_memory` 和 `swd_read_memory`：对齐的 4 字节请求走字读取；2 字节请求目前走逐字节余数路径。
- 本次上位机统一为对齐 32 位访问，不通过读邻接字或两次字节读取伪装原子半字访问。要支持真实 16 位 MMIO，需要明确的探针访问宽度协议与固件实现，再做 ARM 实板验证。
- ARM SVD 的继承、cluster、字段偏移和过滤使用夹具验证；没有连接 ARM 板卡，不能把这些测试说成 ARM 硬件验收。
- HPM 的型号目录来自本地 SDK 描述；目录可解析不等于所有寄存器都有时钟或当前封装存在。未声明的读取副作用仍依赖厂商手册。
- Web 波形为 Float32；大整数可能舍入，精确值使用单次寄存器/字段读取。
- 本轮没有重建安装器或更新全局已安装 Skill。开发源码的 CLI/MCP 和当前源码 Web 服务已验证；正式安装渠道仍是原版本。
