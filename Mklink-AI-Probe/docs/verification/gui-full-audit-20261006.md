# GUI 功能审计与缩放修复（2026-10-06）

本轮实际操作 Windows 原生桌面与 Chrome Web GUI，并使用 STM32F103RET6 和两个 V4 下载器。安装态基线为 0.3.0 / `1acbf856`；最终修复已更新到 0.3.0 / `01d89c60`，安装态结果见下文。有限功能测试不等于长期稳定性认证，旧持续目标和长期验证保持暂停。

## 发现与修复

1. SuperWatch 在 50,000 点、约 200 kHz 下仅保留约 0.25 秒数据，图表却强制扩展为一秒，暂停缩放后开始会出现大片空白。时间范围改为真实保留范围，缩放到全部历史时不虚构额外历史。
2. 暂停消息到达 Worker 时，其环形缓冲可能已超前于界面最后一份摘要。冻结数据响应带上真实快照边界，界面据此重新请求范围，避免暂停后放大历史范围时左侧缺图。仅交互请求增加边界字段，不改变采集协议或逐点读取。
3. 图表所在 Grid 的隐式列宽受 Canvas 固有宽度影响，窄窗口右侧裁切；明确使用 `minmax(0, 1fr)`。
4. Memory 写入后的自动回读会把写入地址改为读取起始地址，导致下一次写入落错位置；只在写入地址为空时初始化，保留用户输入。
5. 新 GUI 窗口的 RTT 自动搜索未使用共享后台已经加载的符号；按显式路径、已连接设备的已加载符号、工程发现的顺序复用原解析流程。

## 采集间隙跟进

用户提供的波形使用采样点模式，数值跳变不连线；导出的时间戳同时确认有真实采集间隙。100 μs 设置下，桌面 CSV 中位间隔 100 μs、最大 1,159 μs，截图时间范围内最大 845 μs。不能仅凭传输 drops 为零判断采样连续。

固件 console 采集线程原来每 100 ms 强制休眠一个 tick，为低优先级任务提供运行机会；看门狗刷新原先依赖屏幕线程。固件 `ded5f2b` 改为高速采集线程直接每 100 ms 喂狗，不再为屏幕主动休眠，保留 DAP/USB/电源任务优先级及 USB 背压等待。

STM32 对应 V4 已升级 UF2 `ed77ec78ad9a4f5cde8206d025aef759082d0695cee678a2459ab25e368bc0c1`。另一次三秒、无 RTT、无内存轮询的原始传输实测：100 μs 设置中位 100 μs、最大 266 μs；全速约 208.1 kHz，最大间隙 418 μs；传输丢弃为零。此对比不是同一 GUI 会话的严格 A/B。剩余抖动尚未消除，不声称硬实时或无间断。

OpenOCD 在八通道 RTT 和 Watch 工作时约 0.279 s 连接并暂停，目标访问被正确拒绝；单步、APP 113,304 字节下载及校验通过，Bootloader 不变。调试后显式重启八通道 RTT/Watch 恢复。首轮验收脚本因仅排空一次缓存便要求异步失效事件立即到达而失败，改为最多 500 ms 排空等待后通过；没有自动重放目标写入。调度回归、运行时回归及 249,087 个 USB TX 边界场景通过。HPM 下载器本次尚未升级。

## 时间栅格与调试打印清理

SuperWatch 时间轴改为按采集时间对齐的 1/2/5 档主栅格，每格五等分，自动选择 μs/ms/s 并标示每格时长。分屏使用同一时间栅格，数组快照保留索引轴。真实浏览器两通道采集验证 500 ms/div、暂停缩放 2 s/div；恢复后保留约 10.4609628 s 时间窗口（新一轮数据尚不足时显示已有数据范围）。

前端和兼容静态查看器共删除 18 处临时 console.log，包括符号元数据、观察行重建和变量添加追踪；保留错误处理以及 RTT 测试工程的必要测试数据。相关 107 项回归通过，生产构建通过；本次是源码 Web GUI 验证，尚未重新覆盖桌面安装包和本地 Skill。

本轮没有新增采样抖动固件改动或新的原始采样统计；266 μs 来自前一轮三秒原始传输短测。约 10 ms 周期较小间隙与电源任务周期相近仍只是线索，需测量任务耗时再归因；不以传输 drops=0 推断无漏采，也不以插值掩盖间隙。

## 后续固件定位：多变量采样与 DAP 时钟交接

确认并修复三个原因：多变量每次读取重复初始化 SWD；采样耗时超出周期后仍额外等待完整周期；OpenOCD 修改调试时钟后应用未恢复显式选择的时钟。普通 RAM/Flash 在持有目标锁的批次内复用已校验读取，MMIO 保持独立访问；恢复时钟只在 DAP 释放、重新附着成功且端口匹配时进行。离线任务临时时钟不覆盖应用档位，采集仍须显式重启。

STM32、30 MHz、仅 SuperWatch、每项三秒原始采样：两个分散变量全速由 17.28k 提升至 35.02k 组/秒，四个由 8.75k 至 18.40k，15 个由 2.36k 至 4.97k。100 μs 设置下，两个变量由 8.84k 至 9.87k，四个由 4.93k 至 9.70k。单字全速约 205.45k（前测 207.83k），不将单次短测差异视为确定回退。各次传输序号缺口和丢弃计数为零，但最大采样间隔仍为 308–483 μs，尚未消除时序抖动。

最终固件另验证 18 种布局、32,575 个精确字节样本，包括 1/2/4 字节偏移 0–3、分散区域、64 字节块和跨 1 KiB TAR 边界。生产代码宿主测试覆盖 MMIO、不完整组、故障、时间预算及 SWD/JTAG 时钟恢复；协议、目标仲裁和调度回归通过，固件编译及 SWD 内存布局门禁通过。

RTT 八通道与四变量 Watch 同时工作时，OpenOCD 约 0.272 s 连接暂停，单步、APP 下载和校验通过，20 KiB Bootloader 保持一致。退出后显式重启恢复约 16.7k 组/秒（时钟修复前约 675 组/秒），八通道 RTT 恢复，未见传输丢弃。

实际安装版桌面首次连接成功，两个变量 100 μs 显示约 9.79k Hz；共享 Web GUI 约 9.85k Hz，暂停、恢复和停止状态正确。测试结束已停止采集。安装版本仍为 01d89c60，本轮未更新 NSIS/Skill，因此前述新时间栅格尚未进入本机安装包。
