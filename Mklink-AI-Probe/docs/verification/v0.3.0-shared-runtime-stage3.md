# 0.3.0 第三阶段：独占任务与 MSC 身份绑定

日期：2026-10-03。分支：`codex/v0.3.0-shared-runtime`，接续第二阶段 `9c7883f`。
后续共享 SDK 与调试 CLI 的进展见[第四阶段报告](v0.3.0-shared-runtime-stage4.md)。
本轮推进主机端任务管理和多设备磁盘选择，没有修改探针固件、WinUSB 或正式安装版。

## 改造结果

原生 CDC 的 flash、erase、reset 现在可以作为独占任务提交，GUI、MCP 与 CLI
复用同一任务入口。任务先检查物理设备身份、连接、已有操作和持续采集，再接受
执行；冲突直接拒绝，不隐式停止采集、不排队。CLI flash 要求明确固件路径，
采用后台当前工程/芯片配置。实际烧录仍调用现有 Device 服务，没有重写底层算法。

任务记录先落盘，再启动硬件工作；每后台最多保留 64 项，包含请求 ID、任务 ID、
状态及有界结果。相同请求 ID/参数在保留期内只返回已有记录，参数冲突拒绝。
关闭客户端不取消工作。重启时未完成任务转为 unknown，不自动重放；异常后的
unknown 不代表未修改目标。记录淘汰后的去重不受保证，旧任务不存在时不能推断
操作失败。当前不提供强制中断原生硬件命令的取消入口。

操作准入同时观察 CMSIS-DAP 在线任务，防止其 HTTP 提交结束后 CDC 又进入目标。
在线任务保留既有停止和状态接口；脱机流式触发保留既有输出接口。共享模式中，
客户端断开后请求仍等待串口线程结束再释放共享准入。按用户要求删除了旧模式的
差异分支，所有此类请求统一等待实际工作结束。
原生任务、在线任务和脱机触发目前仍是不同的业务结果模型，没有宣称全部持久化。

Windows MSC 通过磁盘→分区→逻辑卷关联，再沿 PnP 父节点核对 USB VID/PID/序列号。
只接受唯一匹配的 MICROKEEN 卷，使用卷 GUID 路径，避免盘符被另一设备重用。
同名卷标、USB 序列号缺失/重复、多个候选卷、查询失败都不回退到“第一块磁盘”。
实现参考 [Microsoft 设备实例 ID API](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_get_device_idw)
与[逻辑磁盘/分区关联](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-logicaldisktopartition)。

每探针进程的磁盘绑定同时作用于现有原生文件复制、FLM 查询、脱机部署与磁盘状态。
脱机触发不再接受其他设备的命令口。GUI 后台管理增加磁盘核对按钮与最近任务记录。
PowerShell 被动查询脚本作为包资源交付；身份遍历使用系统 cfgmgr32，不安装驱动。

探针固件升级进入 Bootloader 后的身份尚未建立，共享模式继续拒绝该操作；
Mac/Linux 共享 MSC 暂不支持。开发后台协议升为 4，需要显式退出旧开发后台。

删除 GUI/MCP/已迁移 CLI 的 `--direct` 参数、重复直连函数和 Web 快捷入口旧进程
接管逻辑。共享后台仍使用底层 CDC/Device。独立 dump/watch/分析等 CLI、Python SDK
和独立远程 Agent 尚未迁移，必须先释放同一设备的共享后台；不能宣称所有直连代码已清除。

| 真实 MCP 复位任务 | 对已知 STM32F103 提交 reset、退出 AI 后查询成功结果；重复同一请求返回原任务 |
| 真实 CLI | reset 通过共享任务完成；另一下载器保持连接 |

| 目标运行 | 读取容量为 512 KiB；恢复后 VTOR=0x08005000，RT-Thread tick 两次采样递增；另一探针连接与磁盘文件保持不变 |

首次全量发现流式断开修改影响旧独占契约；用户随后明确要求删除旧模式，已统一
断开语义并更新测试。删除 Web 入口旧参数后补齐协议处理及卸载调用点的回归。
一次定向回归缺少本机 FLM 环境指向，恢复已有资产路径后通过；未提交私有资产。
既有 websockets 弃用、大 chunk、含链接测试目录保留提示继续记录。

测试中曾错误地将 App 的 0x08005000 起址判断为配置问题并改成 0x08000000。
用户说明 Bootloader+App 布局时，已发生烧录、擦除且恢复任务已经提交；停止了
测试编排，没有中断正在执行的后台任务。随后恢复 App 链接起址，重新构建两份
固件，核对地址区间无重叠后合并下载并完整校验，再完成 App 单独更新保留 Boot
区域与运行验证。该过程是测试配置判断错误及纠正，不能归因于后台串写其他设备。
Boot 构建零错误零警告；App 完整构建零错误、四项 RT-Thread C 库既有编译警告。

真实 erase 在已加载正确算法的 flash 之后执行；全新连接直接 erase 的算法准备
不在此次实机证据内。未执行脱机包部署、物理拔插/盘符交换或探针固件升级，未改
VCC。原生烧录复制了目标镜像与所需算法文件，第二台探针只做连接与隔离验证。
截图、日志、设备标识、本机路径和测试固件均留在忽略目录，未进入源码提交。
测试启动的后台和采集结束后已清理。
