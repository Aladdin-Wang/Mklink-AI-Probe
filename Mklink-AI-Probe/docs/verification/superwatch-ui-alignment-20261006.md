# SuperWatch 子字读取、暂停缩放及首次连接修复

## 实际复现与原因

- 原生安装版：`uint8_t vofa_test_count` 约 21.9 kHz，后台与显示一致，并非频率标签换算问题。固件高速批量路径要求四字节对齐，原先一字节请求进入通用读取路径。之前四字节变量的约 200 kHz 验收不能代表子字变量。
- 原生安装版：暂停显示后等待环形缓冲覆盖，再滚轮缩放，曲线消失。主线程冻结视口，Worker 却从仍在更新的环形缓冲提取旧时间段，返回空数据。
- 双下载器：首次连接只执行后台选择并刷新页面，第二次才调用设备连接。

## 修改

- 对符号目录确认的 RAM 范围，将采集请求补齐到四字节边界；保留变量原地址、宽度和符号性进行解码。未知区域、越界补读和外设寄存器保持原访问宽度。交叉边界的值可从两个字中正确提取。复用当前固件高速路径，本次不改固件、SDK、USB接口。
- 暂停/停止时在 Worker 保存一份独立、有限容量的数字历史，缩放与导出使用该快照；恢复、重置和更换布局时释放。仅暂停时复制，连续采集不增加逐点复制。单通道 50,000 点快照最多额外约 0.6 MB，随通道数和实际保留点数增长。
- 恢复/重新开始时保留时间窗口宽度与用户纵轴设置，时间窗口跟随最新数据。
- 选择另一个后台时，在其不可变探针身份下完成一次正常设备连接，再返回切换结果；短暂使用无硬件访问的会话保持初始化存活。不转发旧 COM 口，不自动重试失败操作。

## 验证

- 相关 Python 回归 276 项通过，另组协议/外设/独立查看器与交接回归 69 项通过（部分交接测试重叠）。GUI 全套 886 项通过；生产构建通过。
- 新增类型测试包含 uint8/int8、uint16/int16、uint32/int32、float、bool；偏移 0–3、跨字、截断、重叠变量顺序、未知 RAM、边界和外设不补读。
- STM32 与 HPM5301 真机 48 组：每块板 1/2/4 字节 × 偏移 0–3 × 1/20 μs；每组校验原始字节和有符号/无符号解码。无事件间隙或接收丢弃。STM32 为得到稳定参考值短暂暂停 CPU，完成后恢复；HPM 使用已有静态测试数组，无目标固件写入。
- 源码 Web GUI：同一个一字节变量约 203.8 kHz，短测协议、后台丢弃为零；与原约 21.9 kHz 相比约 9.3 倍。不是所有布局均可达到此速率，跨字/多变量还受总读取量和目标总线影响。
- 源码 Web GUI：暂停后历史超过实时缓冲保留时长仍可缩放并显示波形；暂停缩放至 98.41 ms 后点击开始保持 98.41 ms，停止缩放至 78.728 ms 后重新开始保持 78.728 ms。
- 源码 Web GUI：冷启动选择 STM32 一次连接成功，切换另一台 HPM 一次连接成功。
- 新 NSIS 安装态和本地 Skill 验收进行中；本文件后续补充最终证据。旧持续目标及长期验证保持暂停。

原始日志、截图及按地址验证结果仅保存在忽略的构建目录，不提交设备身份或本地测试工程路径。
