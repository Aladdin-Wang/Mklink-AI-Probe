# 0.3.3 客户连接、卷枚举与 MCP 环境反馈

2026-10-10，应用源码 `350c3c18`，分支 `0.3.3修复分支`，草稿 PR38。
本轮未改固件、Web 资源、安装包或发布渠道。

## 反馈与判断

客户反馈包基于 0.3.2 / Python 3.12，包含测试报告、矩阵和复现脚本。
本轮只读取附件，没有执行其中的脚本，也没有复现其写目标操作。
报告记录 worker 已 ready，但 reset_input_buffer 等待 read_lock 超过父进程
7 秒期限；后续 close 也被阻塞。源码中接收线程持锁进行无限期的 Windows
GetOverlappedResult 等待，而且可以反复重新抢锁，确实存在对应风险。
客户驱动是否另有取消不完成的问题，不能仅凭报告断言。

另外两项有明确环境证据：Win32_Volume WMI 查询返回 0x80041003 权限错误；
AI 客户端无法解析裸 python，且默认缓存目录不可写。历史 flash 任务的
unknown 状态没有足够证据改成失败或成功，仍须查询原任务、检查现场，不能重放。

## 架构约束与修改

- GUI、MCP、CLI、共享 SDK 继续复用同一物理探针后台。USB 身份绑定、应用端口锁、
  后台实例锁、会话租约、目标操作排他与任务去重规则保持原有职责。
- worker 的 read_lock 只协调进程内接收与清缓冲。清缓冲先暂停新读取，再取消
  本 worker 的读请求并限时取得锁；不会解除其他进程的锁、关闭其他后台或抢占设备。
- Windows 完成查询改为非阻塞；未完成时等待读事件最多 5 ms，及时响应新数据并让出
  控制机会。保持 8 个有序请求、128 KiB 原生缓冲及有界输出队列。
- 取消之后必须收割所有读请求，才能清缓冲、重新提交或释放 ctypes 缓冲和事件。
  取消未完成时保留对象引用并结束本 worker，不把活动缓冲交还 Python。
  关闭由控制线程统一执行，接收线程停止、请求收割、串口关闭后才回复成功。
- epoch 仍隔离清缓冲前后的数据；错误帧在输出背压下保留顺序，等待可被关闭中断。
  接收失败后控制命令继续拒绝写入和清缓冲。父进程遇到缺失或无效控制回复时回收
  自己的 worker，避免迟到回复被下一条命令误用；不自动重发原命令。
- WMI 不可用时，通过 SetupAPI 的磁盘设备接口、存储设备编号和卷 GUID 枚举卷，
  再核对完整 USB VID/PID/序列号。枚举后重新检查映射，不按卷标或盘符猜选。
  元数据句柄使用 DesiredAccess=0，不读写磁盘扇区。两条路径都失败时保留权限错误
  与失败阶段；“未选盘”只描述这次发现过程，不推断整个历史烧录任务无副作用。
- 新增 `mcp-config --cache-dir <绝对目录>`：生成当前解释器绝对路径、包目录和
  经写入检查的缓存环境配置。只输出配置，不覆盖用户客户端设置。包内 `.mcp.json`
  仍是通用模板，受限客户端应按 `references/install.md` 生成本机配置。

原生枚举依据微软的 [SetupAPI 接口枚举说明](https://learn.microsoft.com/windows-hardware/drivers/install/enumerating-installed-device-interface-classes)
和 [IOCTL_STORAGE_GET_DEVICE_NUMBER](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-ioctl_storage_get_device_number)。
设备编号只用于本次枚举，不作为跨重插的持久身份。

## 未覆盖范围

本机为 Python 3.14 / V3.6.4，未在客户 Python 3.12 和其受限 AI 账户原环境复测。
WMI 失败回退同时有注入测试和实际原生枚举，但不代表已经复现客户的权限配置。
目标板仍断开，因此本轮不宣称 GD32 目标读写、原生烧录、高速采集性能或 V4 验证通过。
锁饥饿和永久阻塞有可控测试，不能把所有原始 CDC 故障或首次启动离线归为同一根因。
完整的重插瞬间句柄级身份认证仍不在本次范围。

用户继续暂缓管理员安装；此前 NSIS 不含本次修复。PR 保持草稿，需后续候选包
及客户现场回归，不代表正式版已经更新。
