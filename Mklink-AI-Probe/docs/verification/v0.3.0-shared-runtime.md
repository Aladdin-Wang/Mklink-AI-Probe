# 0.3.0 共享后台架构与阶段验证

日期：2026-10-03。基线：`main@d4e73bd`；开发分支：`codex/v0.3.0-shared-runtime`。
本报告记录第一阶段实现和验收边界，不代表已发布或完成安装版、全型号长稳认证。
后续常用 MCP/CLI 与后台管理进展见[第二阶段报告](v0.3.0-shared-runtime-stage2.md)。

## 评审结论与本轮取舍

原评审关于连接生命周期分散、同一 CDC 被多个入口争用、持续采集与普通命令互相
影响的判断，值得优先处理。直接替换成 WinUSB 不能解决目标资源冲突和客户端
所有权问题。本轮先保持 CDC、命令协议和探针固件，统一主机侧物理连接所有权。

`runtime.py` 负责后台发现、进程锁和客户端；`runtime_api.py` 负责认证、会话与
操作准入；`runtime_mcp.py` 适配 AI；`runtime_proxy.py` 适配桌面窗口生命周期；
`probes.py` 负责被动枚举、身份和本机别名。GUI 业务仍复用原有 FastAPI 服务及
采集管理器，通过受限能力表向 AI 开放。此方式降低本轮拆分风险，但还没有把庞大
REST 模块彻底拆成独立应用服务层；长期仍应让 GUI、CLI、MCP 调用公共服务对象。

| 问题 | 本轮处理 | 仍需推进 |
|---|---|---|
| GUI/MCP 各自持有 CDC | 每个物理下载器一个后台；桌面子进程只做代理 | 迁移其余独占 CLI/SDK 和完整 MCP 工具集 |
| 窗口退出导致采集断开 | 后台独立生存；退出客户端只解除会话 | 托盘/后台管理界面、可见的 GUI 会话统计 |
| 并发命令破坏采集 | 操作互斥，冲突返回 busy，不隐式停止其他采集 | 完整任务模型、取消状态和更多资源组合测试 |
| AI 重复采样 | 返回已有 SuperWatch 行、数组快照和 RTT/SystemView 历史 | 更完整的订阅能力及慢消费者指标 |
| 多设备选错 | 稳定身份、明确选择、每设备进程隔离 | MSC 卷到设备身份绑定、多设备远程 Agent |
| 长时间运行失稳 | 有界会话数、会话过期、缓存单行、现有 StreamHub | 24/72 小时 soak、拔插/休眠/故障注入、日志轮转 |

## 多下载器和别名

身份使用 USB VID/PID/序列号的散列，不使用 COM 号或列表顺序。已接入的两台探针
有不同 USB 序列号。V4 固件当前从 OTP UID 生成序列号，因此本机身份识别和别名
不要求修改固件。序列号缺失或重复时使用位置加端口的临时身份，明确拒绝持久别名，
不能将这种设备宣称为可靠跨插口识别。

每个身份有独立 owner/startup 操作系统锁、随机认证令牌、监听端口、Device 和
采集管理器。双客户端同时启动同一身份只复用一个后台；不同身份各自运行。
省略选择且存在多台时，MCP/CLI 拒绝执行；GUI 进入选择页。同一探针多个客户端
共享一个工程和符号上下文，显式冲突不静默覆盖。

别名是本机当前用户目录内的映射，可从配置页或 MCP/CLI 修改，支持中文、检查
重名，换 COM 号后保持。若将来要求“下载器带着别名走”，应增加固件 NVM 读写
协议，定义长度/编码、版本、校验、磨损和复位行为；USB 序列号仍保持不可变，
避免改变 Windows 设备实例和驱动关联。本轮不增加这一固件变更。

多设备时，未绑定身份的 U 盘式升级和脱机部署/触发拒绝运行；在线 CMSIS-DAP
请求必须匹配窗口对应序列号。这是第一阶段明确的功能限制，不是全下载通路验收。

## 生命周期与能力边界

后台只监听本机，检查 Host/Origin；HTTP、WebSocket 都认证。浏览器用短暂 URL
fragment 换取 HttpOnly/SameSite Cookie，随后清除 fragment；桌面代理注入后台
令牌。接口只面向同一用户的本机客户端，不是跨用户隔离或远程权限系统。

MCP 提供九个入口，具体共享能力由 `ping.capabilities` 声明。硬件操作不能通过
旧 WebSocket 任意方法绕开共享准入。读取缓存不会启动第二路 CDC 采样；一次性
内存读取限制为 1..4096 字节，持续采集期间拒绝。启动另一类 CDC 采集不再隐式
替换当前采集。停止/暂停必须尊重其他客户端的订阅。

会话上限 128 个，TTL 120 秒，客户端每 20 秒续期。退出/过期不自动关闭设备或
采集。工作请求被取消时仍等待底层操作结束再释放准入锁，避免超时后第二条命令
进入尚未结束的串流。后台异常不会自动切回直接 CDC，也不会重放结果未知的操作。

普通旧式 CLI、Python Device 和 `mcp --direct` 仍属独占兼容接口；完整烧录、
配置和写入能力迁移、共享后台升级/崩溃恢复、WinUSB 均未在本轮完成。
共享模式暂时禁用直接调用 Device 的旧内嵌 Site Agent，状态接口明确说明原因，
防止绕开共享准入；远程连接仍须使用独占兼容入口。
使用方法见 [共享后台](../../references/shared-runtime.md)。

## 验证结果

验证环境：Windows、Python 3.14、Edge/Playwright、V4 与 STM32F103 工程；第二台
探针只做主机连接与隔离检查，没有确认其目标 MCU。使用源码开发分支和本地构建
前端，未替换已安装的 0.2.3，未刷写探针/目标固件，也未改变 VCC。

| 检查 | 结果 |
|---|---|
| 全量 Python `pytest _maintainer/testing/tests -q --tb=short` | 2479 通过、3 跳过；包含干净环境依赖安装和现场端包检查 |
| 最终共享调度/代理/身份/缓存/Web 入口定向回归 | 139 通过；包含最后补充的订阅与停止竞争、禁用旁路 Agent |
| GUI 全量 Vitest | 762 通过（73 个文件） |
| Vue 类型检查和生产构建 | 通过；输出到忽略的构建目录，未覆盖跟踪的 `gui/dist`；保留既有大 chunk 提示 |
| 双设备、双浏览器 | 后台 PID/端口不同；窗口各自显示对应命令口；关闭一个窗口后另一设备仍连接 |
| 本机别名 | 真实配置页保存中文别名，刷新后恢复；测试结束恢复原映射 |
| 桌面代理 | 真实子进程从选择页切至指定后台；HTTP/WS 转发成功；强制退出代理后两台设备后台仍连接 |
| 停止隔离 | 显式停止第二台后台后，第一台仍连接 |
| GUI 与真实 stdio MCP | GUI 启动 SuperWatch；MCP 空参数订阅复用同一采集；关闭 GUI 后样本序号继续增加 |
| 浏览器错误 | 两类场景均无 pageerror；截图目视检查通过 |

首次完整回归发现工作树未携带本机 FLM 资产、版本元数据未完全同步。验证使用现有
本地算法包和 STCP DLL，修正版本声明后复跑；这些私有二进制未提交。测试使用的
截图、设备标识、工程路径与日志只保存在本机忽略目录。构建包装器对含链接的测试
目录保留检查提示，本轮未强制清除。

后续发布前必须增加实际 NSIS 安装/升级、冻结后台脱离 Windows Job 后的生存验证、
多次 USB 热拔插/休眠恢复，以及至少 24 小时双设备并行采集的内存、句柄、线程、
数据丢失和停止延时记录。短时浏览器与源码代理测试不能代替这些验收。
