# 0.3.2 Keil 仿真后新启采集验收

2026-10-10，产品源码 `b06bd1d7` 冻结 Windows 后台，V3.6.3 应用固件
SHA256 `f3ae3b9c1822b1f62f46e0f65c29f3080e8629616384fa29e83f874799002c1b`。
本报告区分“先采集后启动 IDE”和“IDE 已运行后新启采集”，前者通过不能替代后者。

## 新增失败及对照

- Keil 使用 CMSIS-DAP、SWD 10 MHz、Normal 连接，已进入仿真并运行目标。
  UI Run 禁用、Stop 可用；目标已经越过初始化断点。没有修改供电。
- 从已知 RAM 的 4096 字节窗口搜索 RTT，随后启动四变量 SuperWatch，
  两者异步返回固件 `status 6`（调试器占用）并停止，设备状态始终为已连接。
- 独立读取 RTT 控制块头 24 字节同样在 0.543 秒返回 `status 6`。
  该请求对应 MUX `op 0x11`，因此并非仅采集启动被拒绝。
- 正常退出 Keil 后，无需重启后台、探针或重新连接，同样搜索与采集通过：
  11.503 秒观察中 Watch 增加 10927 次，八路 RTT 各收到 2303–2773 字节。
- 初次测试误用超过当前 AXF 已知范围的 64 KiB 搜索窗口，被上位机 422 拦截；
  已保留该测试参数错误证据，不归因于固件或连接丢失。
- 固件会话正在修复 DAP 写入观察器对 AIRCR 软件复位及 AP bank 1 BD 寄存器的
  仲裁状态更新。V3.6.4/V4.6.8 已构建，尚须精确哈希实测，不能提前宣称问题解决。

## 同批已通过项目

V3.6.3 实际 GUI 自动升级、30 MHz Flash 128 字节采样两档各 30 秒、
RTT8/Watch4/UART 并行及四路在线文件检查通过。时间戳最大样本间隔为
1 kHz 档 1054 微秒、最大速率档 219 微秒，完整性计数均为零。
原在线烧录后自动恢复采集并并行完整读回 512 KiB，426.822 秒通过，内容与备份一致。
下载后未手动重新设置速率的采样吞吐与显式 10 MHz 参考比值为 1.000312；
这是采样时间戳结果，不是物理 SWD 时钟测量。90 秒无业务 RPC 后原会话仍有效。
OpenOCD 在采集运行中 halt/step/resume/shutdown 通过，期间设备保持连接。

## 发布边界

V3.6.4 已通过后台自动升级（11.868 秒），实测固件 SHA256 为
`06e7a6b9a0116627eab57b8b93913ffb0f0b05ae95ba271473f3aef6ba7ccc6a`。
Keil 先运行后新启 RAM 搜索及 RTT8/Watch4，11.896 秒内 Watch 增加 10954 次，
RTT 八路各 2048–2272 字节；全部保持连接，无采集错误。
暂停后新启也通过，Watch 增加 10831 次，RTT 无新输出符合目标暂停状态。
保持原采集做单步、继续运行、退出仿真均通过；继续运行后八路 RTT 恢复输出。

测试前置中的两个差异单独保留：新后台首次 Watch 列表为空，补齐四项后才计通过；
首次普通内存读取尚在 legacy 路径，返回零字节，不是 MUX `op 0x11`。
修复后 RTT 动态搜索和描述符读取走 MUX，只读访问及实际八通道数据已验证。
