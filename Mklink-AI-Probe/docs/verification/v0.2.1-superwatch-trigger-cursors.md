# SuperWatch trigger restart and cursor readouts

## Scope and cause

The HPM documentation hardware review reported an armed single trigger that
never crossed, and a floating time-cursor delta of zero while the footer showed
a nonzero delta. Both defects are in the host viewer; this patch changes no
probe firmware, target program, sampling clock, or transport protocol.

Starting acquisition calls `resetBinaryStream`, which disabled Worker full
sample delivery while leaving the trigger enabled and armed. The summary path
continues painting the waveform but does not evaluate per-sample crossings.
The viewer now rearms enabled triggers after reset, clearing old trigger history
and restoring full sample delivery. Restarting after Done also rearms; disabled
triggers keep the summary-only path.

The floating time-cursor panel sampled the main-thread summary ring, which can
contain only the latest row. Both cursors therefore selected the same value.
The footer and value panel already sampled the visible historical envelope.
All three readouts now use one lookup helper, retaining the ring fallback for
non-envelope data. Envelope readings remain nearest displayed samples, not a
new guarantee of full-resolution interpolation.

## Automated evidence

- Before the patch, targeted regressions failed with detail disabled after
  reset and a floating delta of 0 instead of 20. Value mode already passed.
- After the patch, all 93 WaveformViewer tests passed, including repeated
  single-trigger acquisition resets, disabled-trigger reset, and both cursor modes.
- No physical-device or browser success is inferred from these component tests.

## Chrome hardware follow-up

The documentation task deployed the first patch (GUI footer `4c05426add17`)
and confirmed Armed to Done on HPM hardware. Both time and value cursor panels
matched the footer for six visible channels, including channel 0 delta 135.70
and channel 10 delta -146.38. Evidence remains in the local documentation
evidence directory (`14-cursor-time-fixed.png`, `15-cursor-values-fixed.png`).

That review also found an existing missing capture display path: Done still
scrolled and sample count grew from 3377 to 8576. The follow-up patch installs
the captured points as a frozen main-thread snapshot, rejects late summaries,
batches and envelope replies, and uses the normal backend stop/transport close
path. CSV exports this snapshot instead of unrelated Worker history. Stop
failure keeps the capture and displays an error for a stop retry.

An edge capture retains up to N preceding points, the crossing point, and N
following points. With sufficient prehistory and N=100 this is 201 samples per
channel. Starting again rearms. The capture can exceed the ordinary live ring
capacity without truncation. New regressions exercise 16 channels, batches
straddling the trigger window, late data, repeated runs and stop failure/retry.
All 94 WaveformViewer tests pass. The documentation task then deployed GUI
`7354f9bca571` and completed two Chrome/HPM runs: Done retained 201 points,
transport changed to stopped, the count stayed at 201 after waiting, and
starting again completed another 201-point capture. Local evidence:
`17-single-capture-201.png` and `single-repeat-state.txt`.

The additional CSV regression checks the frozen 16-channel export produces
202 lines including its header, 17 columns including time, and the expected
first/last values. WaveformViewer plus downloadTextFile suites pass 98 tests.
Chrome file-save completion is still unverified: the initial review waited for
a download event, but this browser path uses a Save File picker when available.
No successful saved file is inferred from either the click or the unit test.

The primary task also connected directly to the Chrome extension browser,
opened an independent SuperWatch page, and visually confirmed all three speed
options with medium 10 MHz selected. This supersedes its earlier browser-tool
connection failure; no native desktop automation was used for that verification.

## Reproduction procedure

Use the rebuilt production GUI with the existing backend and target firmware.
Select the 16 waveform channels, medium clock, 1 ms interval, channel 0 rising
edge at zero, single mode, and 100 pretrigger samples. Enable before starting;
verify Armed changes to Done and repeat a new acquisition. Check time/value
cursor panels against the footer at separated positions on a stopped waveform.
The documentation task owns hardware coordination and screenshots. No release
or merge is authorized by this patch.
