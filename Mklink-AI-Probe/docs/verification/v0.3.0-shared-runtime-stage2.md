日期：2026-10-03。分支：`codex/v0.3.0-shared-runtime`。
延续[第一阶段报告](v0.3.0-shared-runtime.md)，本轮完成常用 MCP/CLI 接入与后台管理。
未改动下载器固件、WinUSB、正式安装目录或跟踪的 GUI 交付资源。
后续独占任务与 Windows MSC 身份绑定见[第三阶段报告](v0.3.0-shared-runtime-stage3.md)。

## 实现与使用边界

- 常用 MCP 能力覆盖内存/整数变量读写、寄存器读取、符号搜索、RTT、SuperWatch、
  SystemView 及后台状态。能力表独立为 `runtime_capabilities.py`，接口参数仍由
  现有 REST/类型化服务验证；不开放任意 Device 方法调用。
- 八类 CLI 命令默认复用后台：read-ram、write-ram、read-variable、write-variable、
  device-status、rtt、superwatch、systemview。原有命令提供显式 `--direct` 兼容入口。
  write-ram 在一次操作内写入、回读校验，不在两次独立会话之间暴露校验窗口。
- AI/CLI 开始已有采集时只订阅，参数冲突直接拒绝。会话结束不停止他人采集；自己
  启动的采集存在其他订阅者时也不能停止。GUI、MCP 与 CLI 共用准入及 busy 返回。
- 后台管理页区分客户端退出、停止采集、释放物理连接、退出后台。显示设备身份、
  工程、客户端、采集订阅及当前操作。GUI presence 只用于可见性，TTL 45 秒；
  不成为串口所有者。管理列表使用公开句柄，不暴露 AI 会话凭据。
- 每次新的设备操作核对绑定身份。原设备消失或已连接设备端口变化时拒绝操作，
  要求显式解除旧连接再重连原身份。断线不改绑另一台、不自动重放写入。
- 对共享 GUI 与 MCP/CLI 一致执行内存边界/十六进制校验、整数变量类型及 RTT
  输入约束。旧 SuperWatch inspector 会单独读硬件，采集期间拒绝，改用已有快照。

本轮仍复用现有 API/业务服务。烧录的完整独占任务模型、MSC 卷身份绑定、其余
CLI/SDK/远程 Agent 迁移属于下一阶段。当前操作显示的是同步请求，不代表已经
实现持久任务、跨进程取消或完整恢复状态机。协议版本升至 3，不复用旧开发后台；
升级源码前应显式停止旧后台。

## 验证场景

环境为 Windows、Python 3.14、Edge/Playwright；使用两台实体下载器，一台连接
STM32F103，另一台仅验证探针连接与隔离。使用源码和独立输出的生产前端。

| 场景 | 结果与证据范围 |
|---|---|
| 真实 stdio MCP 读写 | 从 AXF 查询专用测试数组的闲置元素，读原值、写入、读变量校验、恢复并回读；通过 |
| CLI 共享写入 | 同一后台执行 write-ram，回读校验 verified=true；通过 |
| SuperWatch 实时写入 | 使用当前符号 generation 执行类型化 live write，写入与恢复均校验成功 |
| 采集冲突 | 采集中 CLI read-ram 返回 busy，不抢占当前采集 |
| CLI 订阅 | GUI 管理页可见独立 CLI 会话；CLI 结束后原有采集继续 |
| 管理页生命周期 | 真实浏览器结束 AI 会话后采集仍在；再停止采集、释放物理连接；第二台探针保持连接 |
| 显式恢复连接 | 对同一稳定身份显式重连并确认测试变量原值；未声称模拟了 USB 拔插 |
| RTT | 真实 MCP 启动、读取缓存、暂停、恢复、停止；通过 |
| 热插拔身份规则 | 自动化夹具覆盖原设备消失且另一台占用旧 COM，以及原设备返回新 COM；均拒绝误操作；物理拔插尚未验收 |
| 浏览器 | 管理页无 pageerror，生产页面截图目视检查通过 |

测试写入仅使用目标工程预留测试数组的闲置元素，结束时恢复原值；没有刷写
目标或下载器固件，没有操作 VCC。采集和本轮启动的后台均在测试结束时清理。
实机工程路径、序列号、截图、脚本及日志只保存在本机忽略的构建目录。
SystemView 复用现有采集 API 与启动/停止准入，本轮未进行目标上的实际 RTOS 事件验收。
