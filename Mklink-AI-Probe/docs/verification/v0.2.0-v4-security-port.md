# V4 通用安全执行与 VCC 控制移植

日期：2026-09-05。用户换用 V4 下载器和 STM32F103 测试板，要求移植 V3
已验证代码，由用户完整编译并下载后再进行 HIL。

## 范围

V4 已具备与 V3 相同的通用 FLM/CFG 安全执行器和 Pika 命令绑定，以及取消
HEX/BIN 关闭阶段自动复位的修改。本轮保留这些已有工作，补齐：

- VCC 安全关闭优先于后台 VREF 跟随；显式零输出不被残压重新打开。
- 按 V4 GPIOB 接线释放 SWD 驱动和上拉、释放开漏 RST。
- 安全电源循环临时停止自动跟随，维持 V4 原有电压 API，不照搬 V3 的板级补偿。
- 同步 V3 的复位捕获超时、HALT 等待及完整扇区空白确认回退。

芯片支持仍由上位机生成的配置维护，不向探针固件增加芯片型号表。
上位机默认断电 3 秒、残压门限 800 mV，供电恢复后稳定 1 秒；不改变受支持
器件或保护等级。V4 的 ADC、LCD、PWM 蜂鸣器和 RISC-V 路径保留。

## 证据

- 使用 V4 现有编译数据库和 HPM RISC-V GCC，对 power_control、swd_host、
  security_execute、target_flash、file_stream、py_cmd、__pikaBinding 七个
  翻译单元交叉编译成功。第三方头文件警告保留，未做完整链接。
- 从实际函数提取的 10 项 mock 电源测试通过：关闭优先、正常跟随/固定模式、
  三种恢复电压、残压边界、恢复电压错误及跟随设置恢复。
- 当前 SEGGER 工程已纳入 security_execute.c。旧 Ninja 数据库需要重新配置；
  CMake 的 VFS 源文件 glob 已覆盖该文件。
- 本轮无探针/目标板写入，无固件版本或安装包变更。固件源码仅保留在用户的
  本地 V4 工作树，未上传；V3 工作树未修改。
