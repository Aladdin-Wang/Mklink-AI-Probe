# 0.3.2 CHERRYUF2 自动升级兼容

## 实测根因

用户接入 V4 并授权刷入 V4.6.4。原上位机自动升级已成功发送进入 Bootloader 指令，
但随后返回 `manual_required` / “未检测到 Bootloader U 盘”，未复制固件。
Windows 实际已枚举 CHERRYUF2 卷，`INFO_UF2.TXT` 的 Board-ID 为 MicroKeenLink。

根因是部分旧 Bootloader 的 USB 串号描述符布局错误，导致上位机原有身份映射不匹配。
固件会话对照 `msc_bootuf2.c` 与从 `bc4e30b` 起的历史确认：
描述符的字符串字符应从字节 104 写入，旧实现硬编码为 114，晚了 5 个 UTF-16 字符。
实际串号固定为 `00000 + UID32[:27]`，仍为 32 个十六进制字符，完整应用态 UID16
位于 `[5:21]`。不能将这一结论泛化为任意前导零或任意子串匹配。

## 主机最终策略（用户更新要求）

首次提交 `c3c2468f` 兼容了已证实的固定旧串号格式，随后用户明确要求按专属
CHERRYUF2 升级盘名称识别、不强制序列号、兼容 macOS/Linux，且不修改 Bootloader。
最终提交 `e1eee01e` 取代串号门槛：

- 以 CHERRYUF2 卷名识别升级盘，不要求序列号格式、串号匹配或新增标识字段。
  旧 CHERRYUF2 缺失 INFO_UF2.TXT 也能识别；若文件提供了其他 Board-ID 则拒绝。
- 兼容名为 MICROKEEN 且已有 MicroKeenLink UF2 标识的升级盘，普通数据盘不能误入。
- 发送重启命令前记录已有升级盘，排除它们；仅选择唯一新候选，复制前重新确认。
  多候选不默认选第一盘，提示断开其他升级盘或下载后手动选择。
- Windows 使用实际卷名和稳定卷 GUID；macOS 通过 IOKit、diskutil 关联实际卷名与挂载点；
  Linux 通过 sysfs、lsblk、mountinfo 识别。固件枚举允许 USB 串号缺失，普通脱机烧录
  的设备身份校验不因此放宽。两种 POSIX 路径仍检查当前挂载状态，不自行挂载。
- 正常态先确定所选设备及固件型号；USB 串号可用于正常态磁盘辅助绑定。
  已知另一个设备的数据盘不会替代所选设备的数据盘。

V4.6.4 是应用 UF2，本轮没有更新 Bootloader；因此旧 Bootloader 的兼容仍然必要。
固件会话确认描述符错位与缓冲区大小另有 Bootloader 源码缺陷，本次只查证，未刷 Bootloader。

## 验证与限制

最终 116 项测试通过，覆盖固件升级、共享后台准入及三平台磁盘发现；包含缺失/旧串号、
缺失标识文件、错误 Board-ID、预先存在的其他升级盘、多候选拒绝、未挂载/挂载更换拒绝，
以及 macOS/Linux 无串号 CHERRYUF2。POSIX 用例为脱敏系统数据夹具，不冒充实体 Mac/Linux。

真实 V4 从 V4.6.3 自动进入 Bootloader 后，使用修复后的绑定解析恢复升级，
复制精确 V4.6.4 UF2（SHA256
`2684d90424d984d2a2bf5f816fbc80fc30a2d9df60fa35e131c860872bfcff1e`）。
应用态以同一 USB 身份返回，命令版本读取确认 V4.6.4。
此轮经历原流程失败和维护脚本续传，不冒称修改后的 GUI 按钮一次性端到端升级已经通过。

产品升级实现已有等待卷恢复的循环，此现象不是新增产品故障。
