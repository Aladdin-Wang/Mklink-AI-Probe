# 0.3.0 符号重载与会话版本收敛

日期：2026-10-03。承接架构复审 A5，在既有共享 CDC 分支继续开发。

## 改动与复用

原后台文件监控直接进入目标控制区，会在同一路径 AXF 重新编译后停止采集并更换符号；
HTTP 准入看不到这条内部调用。会话只比较路径，也无法识别同名文件换版。

本次把 RuntimeGate 原有的操作锁、任务互斥、取消等待和操作记录提取到
`RuntimeControl.run_operation`。HTTP 适配器与 SourceMonitor 都调用这一入口。
仍使用原 ResourceManager、目标租约、采集管理器及 SymbolCatalog；没有新增调度队列、
消息总线、符号解析器或另一套锁。

```text
HTTP RuntimeGate ──→ RuntimeControl.run_operation ──→ 原 REST 处理器
SourceMonitor ─────→ RuntimeControl.run_operation ──→ 原符号重载服务
                           │                            │
                 任务互斥、操作锁、会话版本        目标租约 / SymbolCatalog
```

- SourceMonitor 保留尚未处理的文件内容指纹。CDC 采集、AI/SDK 会话、连接过程、当前
  操作或独占任务占用后台时延后，成功后才确认已处理的那份内容；切换设备不沿用旧事件。
- 手动 AXF 解析、符号重解析和 C 布局更新同样检查共享会话及采集。首次客户端连接加载
  AXF 仍可进行，附着期间禁止另一次符号配置操作。
- 会话绑定现有 catalog generation 和 SHA-256。普通调用和任务提交都检查版本；
  显式重新附着才更新绑定，心跳只续期。请求取消后仍等待工作结束才释放操作锁。
- RTT 等待提示独立于采集故障状态，保留地址和二进制订阅。重载成功后更新地址并提示
  确认目标固件，再由用户显式启动。失败的相同文件内容不会每秒反复解析。

## 验证

定向 Python 115 项通过，覆盖文件内容待处理/确认、忙时延后、同路径目录换版、任务
提交拒绝旧会话、显式重新附着及取消时不提前释放锁。

全量 Python 首轮为 **2548 通过、21 失败、3 跳过**；失败均位于离线下载模块，原因是
该进程未设置维护者已有的本地 FLM 根目录。设置该环境后，失败模块 **79 项全部通过**，
包含首轮失败的 21 项；没有修改烧录配方或资产。此处保留首轮结果，不写成一次全绿。

GUI 最终全量 **777 项、75 个文件通过**，类型检查和独立生产构建通过，未更新跟踪的
gui/dist。构建仍有既有 Dashboard 大分块提示。截图复核发现成功重载沿用旧故障提示，
已改为普通提示；补测新窗口看到历史重载事件时仍能附着正在运行的 RTT。

真实 Edge 加主 V4 下载器、STM32F103RET6、MCP stdio 和共享 SDK 验证：

1. GUI 开始 RTT，MCP 订阅，SDK 保持连接；修改忽略目录中的 AXF 副本内容。
2. 后台显示 deferred，目录版本保持不变；GUI 地址、暂停按钮和 RTT 显示保持，MCP
   仍可读取历史。手动解析被 HTTP 409 拒绝。
3. AI/SDK 全部退出后，GUI 采集仍继续；显式点击停止才允许重载。generation 从 1
   增至 2，SHA-256 改变，后续轮询不再次解析，也不自动重启采集。
4. 恢复原 AXF 后显式重新附着 SDK，Boot 前 20 KiB 逐字节一致、VTOR 为
   0x08005000、tick 推进。没有烧录、擦除或修改下载器固件及 VCC。

最终构建的浏览器闭环和截图已复核，无 pageerror 或 HTTP 5xx。测试后台全部退出。
同路径旧会话拒绝、任务竞争及取消保持锁是模拟回归；没有向真机注入危险硬件任务。
私有日志、脚本、符号副本和截图留在忽略的 .build，不提交标识或用户工程路径。

## 边界与下一步

这次收敛的是符号重载边界。其他资源策略仍有部分位于 RuntimeGate，不能声称整个
应用服务层已经完成。版本拒绝是保护措施，不证明新 AXF 与目标已烧录的固件一致。
自动重载只发生在空闲状态，不自动启动采集、刷机、重连或重放硬件任务。

A6 的旧 MCP 实现及能力目录、A7 的稳定锁目录与共享契约 CI、bfcache 恢复继续排在
后续。第二只下载器本轮只重新枚举；双设备长稳、操作中拔插/休眠及 NSIS 安装升级
仍未验收。WinUSB 和下载器固件保持原计划，当前不改。
