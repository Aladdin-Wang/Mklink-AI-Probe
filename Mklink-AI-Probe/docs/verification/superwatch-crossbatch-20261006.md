# SuperWatch 跨批连续调度实测

本轮继续优化下载器应用层，保留这项改动。收益主要是定时采样恢复正确平均节拍；全速吞吐只有小幅变化，没有实现采集与传输并行，也没有消除批间空隙。

两台 V4 已升级 UF2 `4682f9f09af7476635b07a5761f1d6f80e23e171e0a674f50e25250d2a1bc88d`。基线为上轮 `bee9ddf` / UF2 `48a309b9ac6a72fe0b3fc5cc8255a779e0efadcdae6e4ac3595e85b9b789a3e9`。没有修改目标板源码、SDK、Arm2D、MicroBoot，没有增加 WinUSB；CRC32 和帧格式保持原状。

## 实现与范围

- 在现有采样内核之间传递 64 位绝对发起时刻，下一批沿用上一批的节拍。打包、发送准备及下一批总线设置利用末尾读取后的剩余周期；不再按每批重新起算。
- SWD 最后的 RDBUFF 和 HPM 最后的 SBA 状态读只负责取回、验证已发起的数据，立即排空，不为最终取回额外等待采样周期。没有额外预读，故障批次仍整体拒绝。
- 时间戳取自发起相应目标读取请求之前的硬件 cycle counter，修正旧版把响应取回时刻记给前一个样本的问题。多变量记录使用第一项请求发起时刻，各变量仍依次读取，不能当作原子快照；请求时刻也不是逻辑分析仪测得的目标存储器访问瞬间。
- 延迟不超过一个周期时保留原相位，后续间隔可能略短以恢复节拍；超过一个周期则从当前真实发起时刻重新定相，不循环补采全部错过的样本。所有发布的时间戳都来自真实读取时钟，没有插值或补点。
- MUX 分组快路径（合格的四字节对齐、最多 16 个字、周期不超过 1 ms）使用跨批时钟。非对齐/小字节/其他范围仍走已验证的普通读取；长周期普通路径未在本轮改写。
- DAP 预约在等待和读取边界检查；先排空、校验，再释放目标锁，打包不持有目标锁。停止、新配置、读错和 DAP 接管清除跨批时钟，旧采集仍须显式重启。
- 复用原线程、样本区、看门狗策略和共享等待辅助函数。没有增加定时器中断、双缓冲、动态分配或循环打印；RTT 仍按 1 ms 轮询，DAP/保护优先级及显示最后的策略保持不变。

## 相邻版本对比

相同目标程序、30 MHz 调试档位，仅 SuperWatch，RTT 关闭；单个配置各约两秒。四变量是四个相隔 16 字节的 32 位地址。组/秒由真实设备样本时间戳计算，不是 GUI 刷新率。两版时间戳语义有上述校正，批间数据应结合总体吞吐理解；百分之几的小幅变化包含短测、缓存和调度波动，不能承诺固定提升。

全速单变量本轮从 STM32 239.9k → 245.7k、HPM 127.1k → 129.6k，约 +2.4% / +2.0%；四变量约 +0.7% / +0.6%。这些小幅差值不足以宣称稳定的百分比性能提升。后续单次扫频的 STM32 全速约 242.9k，说明同一新版也有波动。全速仍无空闲周期容纳组帧，跨批节拍本身解决不了这一瓶颈。

## 回归与边界

- 原生生产代码十组测试通过：MUX 编解码、SWD 批量读取、旧批量输出、供电换算、DMA、USB TX、采集调度、运行时、目标锁及 SBA。新增断言覆盖跨批打包耗时、最终排空不多等一周期、长延迟重新定相、DAP 在等待期间接管、64 位计数跨 32 位边界、停止/重配/epoch 清理。五种 SBA 编译配置及每个 DMI/SWD 故障点通过。
- STM32 和 HPM 各 18 种布局，分别 33,854 和 33,840 个样本逐字节一致，包含 1/2/4 字节、偏移 0～3、分散区域、64 字节块及边界。
- 两目标、单/四变量的 1、2、3、4、5、8、10、15、20、50、100 μs，共 44 种配置扫频完成。小于读取耗时的设置自然饱和，1 μs 仍表示显式全速；未恢复估计的 20 μs 阈值。
- 两目标分别在 1 ms 等待模式和全速模式，RTT 与四变量 Watch 并行时运行 OpenOCD。启动至 halt 约 0.27～0.28 秒（包含 PC 进程启动，不是锁抢占延迟）；暂停、单步、原测试 ELF 下载/校验、运行、显式恢复采集均通过。STM32 两次 Bootloader 20 KiB 字节保持不变。
- DAP 持有时 MUX 目标访问返回 busy，协议 echo 可用，旧 RTT/Watch 失效而不自动重放。STM32 RTT 八通道均恢复；HPM 当前目标只有 RTT0 活动，只验证 RTT0。
- 本轮性能、布局、扫频及抢占测试未发现传输序号缺口或 Watch/RTT 缓冲丢弃。这不等于目标信号在采样空隙内没有变化，也不等于没有漏采；物理采样抖动仍存在。
- 最终生产编译和 SWD 固定布局检查通过。ILM 使用 128,270 B、余量 2,656 B；DLM 使用 129,864 B、余量仍 392 B；AHB 使用 18,693 B、余量 13,980 B。相对基线 AHB 增加 12 B（64 位时钟及结构对齐），ILM 增加 278 B；没有新增任务栈/堆分配。

## 下一步与交付边界

这项优化值得保留，尤其是 100 μs～1 ms 定时采样。若继续压缩全速批间隙，应测量增量打包/CRC 与 USB 队列工作能否分散到采样等待空隙，并评估新增状态复杂度；本轮未实施这种更大的改造。不能通过屏蔽必要中断、降低 DAP 或电源保护优先级来伪造平滑时序。

本轮只有固件及验证报告；安装包和本地 Skill 未重新生成。源码时间栅格仍待后续安装交付。长期验证和持续目标保持暂停，本轮不是发布认证。
