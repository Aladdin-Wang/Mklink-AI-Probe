# 合并 HEX 与在线烧录连接方式回归

日期：2026-09-03。分支：`codex/v0.2.0-development`。

## HEX 故障与修复

用户提供的 GD32F303xE HEX 有两个合法的 05 型启动地址记录，位于第 449、11304 行，分别为 `0x08000131`、`0x08008131`。原有预检查接受它，但实际编程与校验又交给另一解析器，导致先擦除、后报 `Start Address Record appears twice`。

修复后预检查、编程和校验共用严格的数据记录解析。启动地址只是入口元数据，不参与写入地址选择；合法的重复 03/05 记录可以接受，校验和、重叠、EOF、溢出与资源限制仍严格检查。编程将所有独立数据段通过真实 pyOCD `FileProgrammer.add_file` 排队后一次提交，不填平段间空洞，不修改原文件。

原始客户文件的离线执行准备验证：

| 数据范围（右端不含） | 字节数 |
| --- | ---: |
| `0x08000000–0x08001BE4` | 7,140 |
| `0x08008000–0x08032618` | 173,592 |

合计 180,732 字节。真实 FileProgrammer 的暂存结果与校验迭代得到的字节完全相同；提交测试替身不接触硬件。原始客户固件、截图及本机日志不进入 Git，也没有将 GD32 固件写入 STM32。

文件快照在设备连接及擦除前复查。复制期间除文件元数据外还比较源内容哈希，覆盖 Windows/共享文件系统同大小、时间戳不变的内容变化。

## STM32 真机与连接方式

Browser 插件控制实际 WebGUI；MKLink V4、STM32F103RE、1 MHz，使用现有测试工程 HEX。应用数据范围 `0x08005000–0x08020060`，共 110,688 字节，仅擦除覆盖扇区，未擦写低地址已有引导程序；未操作加锁、解锁、VCC 或全片擦除。

修复前，“连接后暂停”在算法 Init 出现 HardFault（IPSR=3），“保持运行”出现首地址读回不符，“复位下连接”加硬件复位通过。只读寄存器诊断表明失败链路的算法准备复位前后 PC 和 CONTROL=2 均未变化，RTOS 的进程栈状态被保留。

原代码只把“硬件复位”用于任务尾部，算法准备仍使用默认软件复位。现在将明确选择的硬件复位传入会话；算法执行前检查异常状态与栈/权限上下文，不合格时在擦除前停止，不自动改成物理复位。任务尾部若目标仍暂停、锁死或处于复位，报告复位失败，并禁止断开时误运行遗留 RAM 算法。

首个下载器的实际对照（末项运行状态检查加入前的成功记录，不作为该新增检查的验收）：

| RST 接线 | 连接方式 | 复位方式 | 观察结果 |
| --- | --- | --- | --- |
| 接入 | 暂停／保持运行／复位下连接 | 硬件 | 三组均完成编程、读回校验和复位 |
| 断开 | 暂停／保持运行 | 默认／软件 | 四组均完成编程、读回校验和复位 |
| 再接入 | 暂停／保持运行 | 默认／软件 | 四组复现上下文未复位，新增保护在擦除前拦截 |

此对照证明接线会影响该下载器与目标组合的软件复位，不能单凭 GPIO 软件配置推断外部电路是推挽或开漏。用户随后更换为已改开漏 RST 的 V3，并确认新版 V4 同样采用开漏 RST；后续以开漏硬件为前提，不为旧 V4 增加专门兼容或复位回退。上述上下文与运行状态检查是所有下载器共用的安全检查。本轮不修改下载器固件。

最终源码在 V3、RST 接入、同一 STM32 与 HEX 上的 WebGUI 回归：

| 连接方式 | 默认复位 | 软件复位 | 硬件复位 |
| --- | --- | --- | --- |
| 连接后暂停 | 通过 | 通过 | 通过 |
| 保持运行 | 通过 | 通过 | 通过 |
| 复位下连接 | 通过 | 通过 | 通过 |

九个独立 GUI 任务均为 succeeded，耗时约 9.7–11.1 秒。每组包含覆盖扇区擦除、HEX 编程、逐字节读回校验、复位后 RUNNING/SLEEPING 状态检查及断开；未出现解析错误、校验失败或复位失败。此运行状态检查不等同于完整业务功能验收。

随后用户拔掉 V3 的 RST，保持同一测试板及其他接线，补测结果：

四组均从 WebGUI 发起，完成擦除、编程、读回校验、复位运行状态检查和断开。最终下载后，按现有 MAP 中的变量地址，通过公共 CLI `dump-memory` 在同一普通命令会话采集 3 个样本、100ms 间隔：`g_demo_sample_count` 与 `g_mklink_heartbeat` 均为 139→140→141，三帧 flags=0，无解析丢帧/CRC 警告，确认应用主循环继续运行；采集结束停止流并关闭连接。端口发现自动识别替换的 V3，没有复用旧 V4 不存在的命令口。此补测未修改源码、目标固件或供电。
