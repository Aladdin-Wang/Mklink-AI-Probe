# 0.3.1 首轮审查与桌面启动修复

日期：2026-10-08。开发分支：`codex/0.3.1-fixes`，基线：`bc1e8327`。
本记录覆盖启动、共享后台生命周期、旧固件 RTT 兼容和客户反馈中的锁/端口路径；不是全仓或全部硬件组合认证。0.3.1 尚未发布。

## 客户问题与证据边界

客户报告 Windows 10 的 0.3.0 桌面提示“无法连接本地服务”，同机 Python CLI 枚举及目标通信成功。冻结代理完整启动链在 15 秒内未完成、60 秒内成功；旧固件多通道 RTT 报错。这些是客户提供的观察，客户设备标识和完整日志不入库。

源代码确认 Tauri 只等待地址文件 20 秒，超时后 `terminate_sidecar_tree` 会关闭 Job 并杀掉尚在启动的代理；前端也只轮询地址约 20 秒。代理完成自身 onefile 解压/导入后，还要启动独立 onefile 共享运行时，原内部等待预算已经是 45 秒。外层更短的截止时间可以直接打断正常冷启动，与客户现象一致，但尚未在客户原电脑回归。

RTT 线程异常会结束该采集，不会直接终止整个服务。共享运行时仅在无窗口、无会话且无在途工作的情况下空闲退出。仅凭日志顺序不能认定“RTT 异常杀死后台”。代理此前虽定义了 HTTP 窗口登记接口，但没有独立续租，实际保活依赖前端加载后建立的 WebSocket；因此慢加载或页面断开确实存在空闲退出窗口。

## 已修改

- 共享运行时启动预算 60 秒，桌面外层 120 秒，前端地址等待 125 秒，覆盖两次冷解压。超时依然有界；没有复用其他 onefile 进程的临时目录。
- 桌面代理从自身 lifespan 开始每秒续租窗口，退出时释放，只保活已选中的同一后台，不重新连接目标或重放操作。页面未加载、刷新或 RTT 失败不会撤销这个窗口租约。代理被强杀后正常 TTL 仍会过期。
- Tauri 启动、重启、监控和退出串行操作同一代理；耗时原生命令移至后台线程。关闭桌面可取消启动等待；监控不会把正在重启的进程判死。前端慢重启期间保留“启动中”，合并重复点击。
- 旧固件多通道/通道 3–7 请求在 HTTP 启动事务和采集线程之前返回 422，提示选择单个 0/1/2 通道或升级固件。保留单通道能力；不静默丢弃用户要求的通道。能力查询在工作线程执行，避免阻塞 HTTP 事件循环。
- 启动失败时不再把加载状态写成“本地服务已就绪”。

## 已检查但不是当前根因

- 动态端口：原有代码从带实例身份的地址文件读取端口，同时更新 REST/WebSocket；8766 是运行时占用 8765 后的合法选择。
- 枚举：现行发现路径被动枚举 USB/MI_04，不扫描打开所有 COM 口；未发现旧 `MKLINK_AUTO_CONNECT` 路径残留。客户 com0com 历史不能直接解释当前问题。
- 锁：运行时用操作系统锁；本地资源状态在 Windows 调用 `GetExitCodeProcess`，不会仅凭 `OpenProcess` 成功认定仍存活。不批量删除旧锁文件。
- AI 展示窗口只选择支持 presentation 的活动 WebSocket；代理保活记录不会成为可展示窗口。
