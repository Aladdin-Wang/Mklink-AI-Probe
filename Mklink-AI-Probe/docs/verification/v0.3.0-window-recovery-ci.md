# 0.3.0 窗口恢复与共享契约 CI

日期：2026-10-03。基于 e8b5f63，继续处理 A4 的窗口生命周期和 A7 的回归门禁。

## 改动

共享窗口原先收到 pagehide 后永久清除心跳及事件监听，浏览器从往返缓存恢复同一文档
时 Vue 不会重新挂载，窗口因此永久离开后台管理列表。

`sharedRuntimeView` 现在区分暂存和销毁：persisted pagehide 暂停心跳、解除当前窗口；
persisted pageshow 登记新窗口身份并恢复心跳。新身份避免前一次延迟 release 撤销恢复后的
窗口；重复 pageshow 不产生额外计时器。普通离开和组件卸载仍永久清理。
只调用现有 view 接口，不附着设备、不重连 CDC、不重启采集，没有新增后端会话表。

新增 `.github/workflows/shared-runtime-checks.yml`，PR、main 推送和手动调度运行：

- `shared-runtime-contract`：Windows/Python 3.12，安装项目 MCP 依赖，验证共享准入、
  独占任务、USB 身份、MCP/CLI/SDK、代理及跨进程端口锁，共 120 项。
- `shared-gui-contract`：Windows/Node 24，npm ci 使用锁文件，验证 App、窗口恢复、
  后台健康、运行端点和后台管理，共 28 项；另执行类型检查和生产构建。

两项均使用既有 build_workspace.ps1，保存 JUnit 报告，生产资源输出到忽略的 .build。
复用已有治理工作流的触发/权限方式和固定 Action SHA；未改分支保护规则、签名或发布流程。
治理检查 feedback-contract 保留，新工作流独立报告应用契约。测试不依赖私有 FLM 或探针。

## 本地验证

新增恢复用例在修复前失败，修复后与 App、旧浏览器租约、健康和端点相关的 30 项通过。
按 CI 的最终选择执行 Python **120 项通过**、GUI **28 项通过**，并生成 JUnit；生产
类型检查和构建通过。未执行应用全量、GUI 全量或 NSIS。既有 Vue 生命周期测试警告、
Node localStorage 实验提示和构建包大小提示仍存在，不将提示隐藏成零警告。

主 V4 + STM32F103RET6 + SDK + 真实 Edge，使用本轮生产资源：

1. SDK 运行 RTT，GUI 导航离开、返回、多窗口打开和关闭时，后台窗口计数正确，RTT 保持。
2. 在真实页面上受控触发 persisted pagehide/pageshow，文档未重建，窗口以新身份恢复；
   不触碰目标连接或采集。截图检查通过，无 pageerror。
3. Boot 前 20 KiB 不变、VTOR 为 0x08005000、tick 推进；未复位、烧录、擦除、改时钟或
   VCC。第二只仅枚举，测试后台已退出，私有脚本和设备标识留在 .build。

**原生往返缓存命中未完成验收。** 首轮浏览器明确报告 response-cache-control-no-store，
返回实际采用整页重载，不能把它写成缓存命中。隔离浏览器中尝试启用 Chromium 的
no-store 缓存实验参数后，离开导航超时；撤回参数后普通导航通过。产品缓存头未修改。
因此当前证据是单元测试 + 真实浏览器受控恢复事件 + 普通返回，不等于所有浏览器原生
缓存/冻结行为已认证。后续在允许原生缓存的环境补验。

实验参数参考 [Chromium 开发讨论](https://groups.google.com/a/chromium.org/g/blink-dev/c/mcOiteClYSo/m/rElGuT2IAAAJ)，
仅用于隔离验证，不加入产品启动选项。GitHub 实际结果以该提交的两个检查为准。
