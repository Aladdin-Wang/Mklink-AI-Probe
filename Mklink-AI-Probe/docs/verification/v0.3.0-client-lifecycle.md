# 0.3.0 共享客户端生命周期收敛

## 复审结论

原 RuntimeClient 没有把 connect/call/start_job 与 close 排序。MCP 同步工具由线程池
执行，退出可能越过仍在途的请求；attach 尚未返回时退出，还可能在退出后留下会话和
续期线程。另一方面，detach 响应失败时 session_id 没有清空，已经调用 close 的 SDK
还能使用旧会话发送命令。MCP 的普通工具还会隐式构造默认客户端，提前固定工程目录和
名称，后续显式 connect 不会重新采用构造参数。

## 改动及分层

- RuntimeClient 为同一客户端的 connect、call、任务提交和 close 排序；其他客户端
  独立执行，心跳不取该锁。该锁负责客户端生命周期，后台操作锁仍负责设备资源准入。
- close 清空本地会话后才发送 detach；响应丢失仍报错，但再次 close 不会重复发送，
  普通调用和任务提交都要求重新显式 connect。保留 info 供只读任务查询使用。
- MCP 仅在 connect 中创建客户端；普通工具取得已有客户端，不再隐式构造。原 holder
  锁继续保护对象的创建/移除，公共 RuntimeClient 处理请求与退出顺序。

没有加入客户端命令队列、自动重连、CDC 直连回退或硬件重试。close 等待本客户端
已进入的同步请求返回/超时，不表示取消后台已提交任务；后台仍独立记录未知结果。

## 验证

新增 5 项回归在修改前全部失败，分别覆盖 detach 响应丢失、普通调用/任务提交/attach
与 close 交错、MCP 未连接时的隐式构造。修复后 SDK/MCP/CLI 定向 43 项通过，CI 同集
后台契约 **125 项通过**。模拟任务提交不实际操作目标。

真实 Edge、MCP stdio、SDK 与 V4/F103 运行：

- GUI 启动 RTT，另一 SDK 保持附着。三轮并发 MCP 历史读取/退出/重连后，没有遗留 AI
  会话，GUI RTT 和 SDK 保持；退出后的历史调用要求 connect。
- 故障注入仅在 SDK 的 detach 响应边界：后台已处理 detach 后向客户端抛出响应丢失。
  第二次 close 不发送，旧 SDK 调用被本地拒绝；显式重新连接后继续共享既有 RTT。
- Boot 前 20KiB 内容不变，VTOR 保持 0x08005000，tick 推进。未复位、烧录、擦除、
  改时钟或 VCC。第二只下载器重新枚举，仅被动登记。
- 无 pageerror/HTTP 5xx，截图已检查。结束后后台退出，系统端口锁释放。

GUI 本轮未修改，使用前轮已构建资源。私有测试脚本、日志和截图留在忽略的 .build。
响应丢失是受控注入，不等同于物理拔线、休眠或长稳验收。远端 CI 以精确提交状态为准。

## 第二轮：续期线程不能跨越附着生命周期

继续复审发现：显式 attach 成功时，原实现只检查旧心跳线程是否仍存活。旧续期请求若
正在等待响应，新附着会沿用该线程；旧请求随后失败退出，新会话失去续期。close 的
有界 join 超时后再次连接，也存在这个问题。清除并复用旧 Event 还可能使旧线程继续运行。

每次成功 attach 现在停止旧续期，复用既有有界等待，再为本次附着创建独立 Event 和
会话快照。旧线程晚返回只能结束自己的循环，不能读取新 session_id 或使用新停止信号。
停止/等待提取为一个公共私有辅助方法，close 与 attach 共用。attach 失败不会替换原心跳。
仍不自动重新连接，续期失败后需显式 connect；没有新增调度器或重试服务。

新增复现用例修改前失败，随后扩展为 4 种交错：新/同会话重新附着、close 后连接、
旧响应迟到成功或失败。共享 CI 同集 **129 项通过**。

真实 Edge/MCP/SDK 再次运行前述生命周期验收，并对旧 SDK 心跳注入超过 6 秒有界
退出等待的延迟。新附着正常续期时旧线程仍存活；释放旧响应并模拟失败后，新心跳继续，
GUI/AI RTT 保持。Boot 不变、VTOR 正确、tick 推进，无设备写操作，后台最终退出。
这是受控响应延迟，不代表拔线、休眠或长稳验收。

首轮测试脚本错误地缩短了注入阻塞的等待时间，引起测试线程断言；该轮心跳证据作废。
修正为独立等待并增加“新续期启动时旧线程仍存活”的断言后，完整重跑通过，没有线程异常。
原始失效记录和修正后的日志均保留在忽略的 .build。
