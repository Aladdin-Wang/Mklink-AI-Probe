# 0.2.3 在线烧录扇区几何修复验证

## 原因与范围

截图中的 `STM32F767xG` 同时带有覆盖 `0x08000000–0x08100000` 的 `STM32F7x_1024dual.FLM` 和 `STM32F7x_1024.FLM`。前者首扇区为 16 KiB，后者为 32 KiB。旧接口把两套扇区表合并，镜像检查正确地判为冲突；页面却没有选择 FLM 的入口，实际任务解析器还会自动选第一套算法。因此页面一直报“几何未验证”，也无法安全地解除这个阻塞。

审计本地内置清单的 7059 个型号：476 个型号包含不同扇区声明，但大多数算法作用于不同地址；真正存在地址重叠且声明冲突的是 27 个型号，包含 STM32F765xG、STM32F767xG、STM32F769xG。另有 26 个算法没有扇区表，其原始 FLM 用当前 pyOCD 解析器均无法解析；它们继续禁用扇区擦除和普通烧录，不能从容量推算扇区布局。

## 修复

- 重叠且布局不同的内置 FLM 在页面显示选择框。镜像检查、内存映射、任务提交和实际加载的 FLM 使用同一算法 ID。切换选择会废弃旧检查结果并重新检查。
- 未选择时不提供混合扇区表；右侧面板说明需要选择实际 Bank 模式。直接调用任务接口进行擦除也不会隐式选第一套算法。任务算法选择与镜像检查不一致会被拒绝。
- 所选内置 FLM 与覆盖同一地址的自定义 FLM 冲突时明确拒绝，避免检查使用一套几何、实际加载另一套算法。
- Pack FLM 提供可变扇区范围时，优先使用该范围，即使 pyOCD 的 `blocksize` 有值。缺口、重叠和不完整尾扇区保持几何不可验证，不把截短空间伪装成完整扇区。

## 验证

- 使用真实内置 `STM32F767xG` 目录与镜像检查器：未选算法时没有可验证扇区；选择双 Bank 后首扇区为 16384 B，选择单 Bank 后为 32768 B。
- 真实 Chrome 先访问当前开发 Web，再访问生产构建静态资源与隔离的当前源码后端：未选择时右侧提示冲突且开始按钮禁用；双 Bank 和单 Bank 分别显示 16384 B 和 32768 B，选择后按钮恢复。只上传了临时 32 B 测试 BIN；未执行擦除或烧录。
- Python 回归覆盖重叠选择、任务算法绑定、自定义 FLM 冲突、全片擦除拒绝、Pack 可变扇区优先级和不完整扇区尾部；全量 2326 通过、2 跳过，最后一处冲突保护的定向回归另有 1 项通过。GUI 回归覆盖选择、重新检查、扇区提示和任务参数；全量 723 通过，最后的按钮门禁改动后定向回归 97 项通过。生产 Web 构建成功。

## 验证边界

没有连接 STM32F767xG 真机，也未核对目标板的 Bank 模式选项字节。本次验证证明元数据、接口和浏览器行为一致；实际擦写仍需要对应型号的真机验证。当前已安装的旧候选 0.2.3 程序未包含本次修复；本轮只更新开发分支与草稿 PR。
