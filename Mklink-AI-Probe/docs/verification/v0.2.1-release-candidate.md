# 0.2.1 发布候选验收

本轮执行日期为 2026-09-14 至 2026-09-15。范围是发布前回归、应用更新仓库迁移准备、Windows 安装包生成及本机覆盖安装。尚未发布 0.2.1 Release、版本标签或更新索引。

## 更新仓库迁移

- 0.2.1 应用和 Skill 默认从 MicroKeen/Mklink-AI-Probe 的 `release/latest.json` 检查更新。
- Gitee Aladdin-Wang/Mklink-AI-Probe 的 `updates/latest.json` 保持原址，且其清单继续引用 Gitee 资产。
- 旧 GitHub Aladdin-Wang/Mklink-AI-Probe 的 `updates/latest.json` 在桥接发布时同步更新，旧用户先取得 0.2.1，随后由新安装代码切换更新源。
- 发布工具在两个 GitHub 仓库和 Gitee 上传相同的版本资产，完成公开下载校验后才写更新索引；跨仓库索引写入不是原子事务。
- 应用标识、更新公钥、安装路径策略不变。固件更新渠道独立，本次没有改写探针固件。

迁移兼容测试覆盖新旧渠道、Gitee 后备及桌面/运行时默认地址一致性。公开索引只读核对均仍为 0.2.0；这不是已完成在线自动升级的证据。

## 安装验收发现并修复的问题

从旧 Skill 覆盖更新时，清理器删除了旧 `mklink.egg-info` 文件但留下空目录。Python 元数据发现仍把它当作一个分发包，版本值为 `None`，导致 MCP `ping` 的更新检查抛出异常。现在同时清理空的受管根目录；运行时优先读取实际 Skill 代码旁的版本，wheel/冻结安装再回退分发包元数据，空元数据返回 `unknown`。MCP 版本报告复用同一入口。补充真实失效条件的回归后重新生成候选包。

## 正式发布前仍需完成

开发 PR #2 必须经另一位维护者审核并整合到 MicroKeen/main；从整合后的确定提交执行正式签名构建与最终发布检查，再同步三端资产及更新索引。当前本地安装器使用 `--local-bundle`，没有更新签名 `.sig`，不可作为已签名自动更新包发布。完整正式资产集合还包括与该最终提交配套的 Site Agent 包。

本轮不重复改写硬件。既有 ARM/HPM 真机结果和限制分别见四档固化、HPM6E80、选项字节和 HEX 预览验收报告；历史板卡/固件测试结果不自动扩展到所有型号或本轮未接入的硬件。
