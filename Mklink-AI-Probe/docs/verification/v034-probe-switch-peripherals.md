# 0.3.4 下载器切换与外设选择恢复

日期：2026-10-11。开发分支：`codex/0.3.4-fixes`，PR40。

## 问题与根因

客户在同一窗口连接不同下载器时报 `Cannot restore peripheral selection`。后续客户定位到应用工作区的 `.mklink/peripheral-selection.json`，其中保存了旧 `target_id`。

源码确认旧 ID 由 Pack 的绝对来源路径、芯片名和 SVD 路径哈希生成。打包程序解压到不同目录后，即使 Pack 和芯片相同，ID 也会变化。SuperWatch 初始化同步恢复这个可选偏好，并将恢复失败升级为整个设备连接失败。这不是多下载器互斥规则要求拒绝切换。

进一步在真机复现：切回已有 SDK 客户端连接的下载器时，GUI 交接重复提交 ELF 配置，导致 HTTP 409；即使没有其他客户端，也可能不必要地重解析已有符号。

## 修改

- 外设 ID 改为哈希 Pack 名称及版本、芯片型号、规范化的 SVD 相对路径，不再包含安装或解压目录。同一来源仍可匹配旧 ID；已经失去来源路径的旧哈希不能安全反推芯片，要求重新选择，不猜测型号或 Pack。
- 可选外设偏好失效、文件缺失、JSON 无效等不再阻断连接。外设目录为空并返回 `restore_error`，RAM 符号及其他功能继续可用。保存文件保留，用户在外设面板重新选择后写入新稳定 ID 并清除提示。
- 新设备重新准备 SuperWatch 时，移除旧外设采样项和寄存器映射，刷新元数据；RAM 项保留原符号重绑定逻辑。显式加载错误仍正常拒绝，其他初始化失败仍清理未发布连接。
- GUI 跨下载器交接通过 `reuse_connected` 表达“加入已有连接”。后台在当前设备仍连接且端口身份一致时保留其 ELF/芯片/解析器配置；新连接仍按正常参数初始化。显式符号变更继续执行原有所有权和操作保护。

同一窗口通过独立桌面代理切换到所选下载器的后台；每个物理下载器仍由自己的后台唯一持有。打开另一个客户端可选择另一下载器并自动创建或连接其后台。切换不停止其他窗口的采集，不跨设备复用串口；同一物理下载器的多个客户端继续共享一个后台。项目级外设偏好语义保持不变，不把芯片型号绑定到可能更换目标板的下载器。

## 验证

- 最终 17 个相关 Python 测试文件共 594 项通过，覆盖目录迁移/归档与解压形式、Pack 版本区分、旧 ID 精确兼容、失效 JSON/SVD、显式修复、重新连接、两窗口独立切换、切换失败保留旧后台、符号/采集/所有权回归。新增用例接入共享后台 CI。
- 前端 PeripheralWatchPanel、ConfigView、useMklinkApi、SuperWatchTab 共 70 项通过；TypeScript 和生产构建通过，更新受管理的 Web 产物。
- 初次新增代理测试的 MockTransport 响应已被预先消费，出现 `StreamConsumed`；改为真实异步字节流夹具后通过，最终 594 项包含该测试。未因此修改生产代理的流处理。
- V3 + STM32F103：在用户原测试工程中写入失效外设 ID，直接使用原 `build/keil/Obj/rt-thread.axf`，实际连接、RAM 读取和 RTT 日志采集成功。未复制工程、重刷目标、更新下载器固件或改变供电。
- 真实浏览器加载生产页面：连接正常，外设面板提示旧选择失效；显式选 STM32F103RE 后加载 4876 项，警告消失，浏览器错误为空。随后两个不同后台实例冷启动均恢复同一稳定 ID 和 4876 项。
- 用户接入第二只实体下载器后，启动两个独立的生产桌面代理，以两个真实浏览器窗口验证 A→B→A→B；第二窗口始终留在 A。A 上 SDK 持续 RTT 和 126 次并行内存检查，0 错误，符号 catalog generation 始终为 1。两个窗口分别连接不同下载器时正常；关闭 B 的代理释放 B 后，A 仍连接和采集；最终关闭所有测试窗口/代理/SDK，后台列表为空。

本地证据：`peripheral-hardware.json`、`peripheral-cold-check.json`、`handoff-reproduction.json`、`dual-probe-hardware.json` 和浏览器截图，均留在忽略的构建产物目录。硬件身份、绝对路径和原始日志不提交。

## 验证范围

双实体探针切换使用生产 Python 桌面代理和真实 Web 页面；第二只下载器未接目标板，验证连接/后台隔离，不宣称其目标采集通过。Pack 迁移通过路径变换夹具验证；本轮未重新构建或安装 PyInstaller/NSIS 包，不将源码冷启动等同于新安装器验收。未合并、签名或正式发布 0.3.4。
