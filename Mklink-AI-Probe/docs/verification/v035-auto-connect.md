# 0.3.5 拔掉旧下载器后的自动连接修复

2026-10-15，继续 `codex/0.3.5-fixes` / PR43；修改前为 `49b7afb1`。

## 问题与修复

用户未点击断开就拔掉旧下载器，换上另一只后，在自动搜索状态直接点击连接，
收到 `Bound probe unavailable or port changed`；手动选择新端口可以连接。

配置页的自动连接会先调用 `/api/runtime/select`，携带 `connect` 参数而不指定
端口。旧处理只要后台不是 lobby 就立即返回 `same_runtime`，没有检查旧设备
是否已经消失。随后的 `/api/device/connect` 被旧身份保护正确拒绝。

现在显式 Connect 且旧绑定已不在枚举结果中时，重新执行唯一候选选择，不恢复
旧设备的 COM 端口。候选选择在生命周期锁取得后执行；继续使用既有切换事务，
先预留新设备所有权，再停止旧采集、关闭旧句柄、撤销旧目标会话并清空目标状态。
后台进程、HTTP 端口、窗口和独立 UART 会话保持。

旧绑定仍存在时沿用原连接路径，包括相同设备变更 COM 号的情况。没有 Connect
的空选择、直接底层连接、旧 SDK 会话均不能自行迁移到其他物理设备。无候选、
多个候选或候选被占用时拒绝连接，不选择第一项、不抢占其他后台、不重放未知操作。

## 验证

- 修复前新增自动连接用例 7 失败 / 1 通过，复现跳过选择造成的失败。
- 修复后连接切换、重连、桥接身份保护 93 通过；包含断连状态延迟、COM 号复用、
  丢弃旧端口/MCU 偏好、撤销目标会话但保留 UART、无候选/多候选/占用保护。
- 共享 runtime、远程 API、探针、枚举、GUI 连接交接、任务和安全回归 239 通过。
  合计上述 Python 332 通过。
- GUI API、配置页、仪表盘连接逻辑 4 文件 / 89 通过。新增自动搜索 API 回归
  验证不发送旧端口，成功切换后不会再发一次连接。
- 用户明确允许连接/断开测试，并配合实际拔掉第一只下载器、插入另一只。
  Chrome 加载源码后台和现有生产 Web；第一只真实连接成功后直接拔掉，
  界面变为未连接。未选择端口或刷新页面，直接点击连接即连接第二只，
  后台 PID / HTTP 端口保持，设备 generation 从 1 变为 2。
- 第二只设备目标 ID 为 `0x0`：本轮只证明下载器物理切换及命令连接，
  不证明第二块目标板可调试或烧录。未改电压、未烧录目标或下载器固件。
- 测试后明确断开，关闭临时浏览器和源码后台；原安装版窗口保留且已断开。
  本地端点/状态证据在构建根 `artifacts/v035-auto-connect`，不提交设备标识或令牌。

所有测试经 `scripts/build_workspace.ps1`，构建根为 `F:/MKLink-Build`。
Python 测试创建的联接目录按存储规则保留，没有强删。源码后台运行期间一次
并行回归被构建根互斥锁拒绝，未执行测试；后台退出后上述回归完整通过。
