# 选项字节 / OTP 可视化：第一阶段

日期：2026-09-11。分支：`codex/v0.2.1-development`。

## 交付范围

脱机烧录的量产配置区增加配置面板：选择器件和下载器型号后加载描述，点击“读取配置”获取一次快照；当前值和待生成动作分别显示。
ARM 的读保护配置仍使用现有解锁、加锁开关与确认流程，生成相同的安全脚本及 CFG 文件。本阶段不改变固件执行器、VCC 或安全算法。

| 器件范围 | 模型限制 | 本阶段能力 |
| --- | --- | --- |
| STM32F1、GD32F303xE | 现有白名单及 V3/V4 配置 | 读取保护状态；配置解锁前置、加锁后置 |
| STM32G474、PY32F030K28T6 | 现有白名单且仅 V3 | 同上；保留原 V4 禁用限制 |
| HPM5301 / HPM5301xEGx | 描述接口接受 V2/V3/V4；只在 V4 实测 | 公开 OTP 熔丝与影子值只读 |
| 其他器件 | 未开放 | 返回不支持原因，不套用相似芯片地址 |

ARM 描述使用 `offline_security` 已验证配方的 ID、状态寄存器和掩码，并保留算法可用性及哈希门槛。
描述查询不连接硬件；真正读取先验证芯片身份。状态错误或不足四字节的读取会失败，不以零代替。
Web 使用目标调试资源锁，MCP 使用硬件互斥；切换器件/型号或读取失败会清除旧快照，过期响应不会覆盖新器件。

HPM 来源为 SDK 1.11.0 的 `soc/HPM5300/HPM5301/hpm_otp_table.h`、`hpm_soc_ip.h` 和 OTP 寄存器定义。
仅访问 word 0、1、3、68，各读取 FUSE 与 SHADOW 一次，共八次对齐 32 位读取，解释八个字段：
HARD_LOCK、LIFECYCLE_A/B、JTAG_DISABLE、DEBUG_DISABLE、SW_VER、USB_VID/PID。
生命周期、软件版本和锁定位仅返回原始编码，不推断状态转换；没有密钥、UUID、校准区域读访问，也没有 OTP 写入口。

## 三端接口

- CLI：`python -m mklink configuration describe --chip HPM5301 --model V4`；连接目标后的单次读取由 `configuration read --chip HPM5301 --port <端口> --project-root <工程>` 完成。
- MCP：`configuration_description(part_number, model)`、连接后的 `read_configuration(part_number, model)`。
- Web：`GET /api/device/configuration?part_number=HPM5301&model=V4`；`POST /api/device/configuration/read`，JSON 为 `part_number` 和 `model`。

三个适配器均调用 `mklink/device_configuration.py`。`current` 是 ARM 当前保护状态或 HPM 熔丝字段值，`shadow` 是 HPM 影子字段值，未读为 null；`read_at` 是 UTC 快照时间。
描述与读取一致不代表任意选项字节写入已实现。配置脚本复用脱机烧录原有生成入口。

## 验证

- 相关 Python 回归 **103 项通过**：新配置描述/读取、四组 ARM 生产配方解析、型号限制、错误/短读、CLI/MCP/API 一致性，以及原脱机安全生成、MCP stdio 和外设统一回归。
- GUI **24 项通过**：新增面板与原脱机页面；验证不自动读取硬件、熔丝/影子分离、过期响应、失败清空和动作顺序。
- `vue-tsc` 与 Vite 正式构建通过，更新内置 `gui/dist`。保留既有较大 chunk 提示；Python 有既有 websockets 废弃提示。
- HPM5301 实板：CLI 子进程、FastMCP stdio 子进程、Chrome 正式页面依次读取，八个公开字段完全一致；没有刷写目标程序或下载器固件。
- Chrome 页面逐项比对熔丝/影子数值，切换到 ARM 后清除旧快照，HPM 误配 ARM 读取返回 422；无页面 JavaScript 错误。
- Chrome 对 STM32G474/V3 配置解锁、加锁并生成预览，检查脚本中解锁 CFG、固件烧录、加锁 CFG 的顺序；只生成预览，没有部署或执行 ARM 操作。

浏览器验证使用本机独立 Chrome / Playwright 和真实源码 HTTP 服务，无响应模拟。
初次预览验证遇到 STM32F103 Pack 加载等待，改用已可用的 STM32G474 配方完成；V4/G474 被正确禁用，使用已支持 V3 配置验证预览。
本地脚本、日志和截图保存在忽略目录 `.build/reports/device-configuration`。不提交板卡原始值、序列号、固件或 Pack。

## 后续阶段

1. ARM 更多选项字节需要按精确型号描述字段、保留位和重载方式，并扩展当前只比较保护状态/修改保护字节的固件执行器；先用可逆字段和对应 ARM 实板逐项验证。
2. HPM 扩展型号须分别核对 OTP 表和身份判断，不能从外设寄存器目录的全系列支持推导出 OTP 支持。
3. HPM 永久 OTP 编程需专用 ROM API/固件命令、编程前差异与权限检查、独立可消耗测试板验证；不能生成当前执行器不认识的命令，也不能借普通内存写模拟熔丝编程。

当前没有连接 ARM 板卡，不声明新 ARM 读取功能完成实板验收。本阶段未进行 OTP 编程、ARM 加解锁或其他不可逆测试。
源码服务可用；正式安装器、全局 Skill 仍为原版本，本次不是发布资格验证。
最后一次服务重启被自动审批以 `blocked by policy` 拒绝，未提供更具体原因；保留已验证的服务进程。
此后源码仅调整配置说明文案并格式化，服务将在下次启动使用更新后的文案。
