# 0.2.1 application update migration

Release preparation, 2026-09-14. No public indexes or immutable tags are changed by the candidate build.

| Consumer | Primary index | Fallback |
| --- | --- | --- |
| Existing 0.2.0 desktop | Existing Gitee `Aladdin-Wang/Mklink-AI-Probe`, `updates/latest.json` | Unchanged existing behavior |
| Existing Skill/CLI/MCP | GitHub `Aladdin-Wang/Mklink-AI-Probe`, `updates/latest.json` | Existing Gitee index |
| Installed 0.2.1 desktop and Skill/CLI/MCP | GitHub `MicroKeen/Mklink-AI-Probe`, `release/latest.json` | Existing Gitee index |

The migration is carried by the installed payload. It does not require old clients to understand redirects or a new manifest schema. Keep the same Tauri public key, application identifier, NSIS installation mode and executable names. Gitee serves mirror asset URLs, so loss of GitHub does not make its manifest depend on GitHub downloads.

The prepared publisher uploads identical versioned payloads to both GitHub repositories and Gitee before replacing any index. The legacy GitHub index is retained; it points to the new GitHub assets for this bridge release. A failed upload or public verification aborts before index publication. Index updates across providers are sequential, not an atomic cross-provider transaction; a retry may be needed after a partial index push, but every referenced payload must already exist.

Publication requires a clean reviewed `main` at the remote MicroKeen tip, matching version metadata and an exact asset manifest. The publisher pushes only the immutable version tag, never the source branch. The current development PR must be reviewed and integrated before the final source-bound release bundle is built and published. Candidate regression and overwrite installation can proceed before that gate.

Probe firmware has its own manifest and update lifecycle. This application migration does not move or publish firmware assets, nor replace the attached probe firmware.

Regression evidence and installer qualification are recorded in the release qualification report. Local candidate installers without `.sig` are for overwrite testing only and must not be passed to the signed publisher.
