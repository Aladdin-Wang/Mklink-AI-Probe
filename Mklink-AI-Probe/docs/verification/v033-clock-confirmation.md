## 日志结论与证据边界

用户提供的异常压缩包包含版本、CDC 原始报文、共享 SDK 和 Web API 结果。
仅阅读日志与脚本内容，未执行附件脚本。原始材料保留在忽略的本地构建目录，
不提交设备身份、客户路径或原始日志。

- 原始版本回复为 V3.6.4；4/10/20/30 MHz 命令均回显请求值及 SWD 统计，
  没有 `SWD profile=<hz>`。20/30 MHz 的 HTTP 422 和显式回退 1 MHz
  与当前主机保护逻辑一致；请求回显不证明高速内核已确认。
- 各档位 IDCODE 均为 0，统计中 invalid 等于 transfers，现场未识别目标。
  计数为累计值，不能据此推算单次时钟设置的失败数量。
- 对照本地 V3 固件源码：`dap_main.c` 自动扫描失败会清零目标 ID 并把
  `debug_port` 置为 `DAP_PORT_DISABLED`；`py_cmd.c::cmd_set_swd_clock`
  只有该状态为 `DAP_PORT_SWD` 且为标准档位时输出 `SWD profile`。
  因而目标未识别可解释该组合现象，不需要假设 V3 不支持高速或固件必然过旧。
  `cmd.get_idcode()` 读取固件缓存，日志不能确定供电、接线、扫描或目标状态的具体根因。
- 日志与此前截图的端口及探针身份不同，不能证明两份材料来自同一物理设备。
  这里分析的是同类症状；也没有客户固件二进制哈希来证明与本地构建完全相同。
- 后台另有 Python asyncio socket 关闭阶段 WinError 10054；后续仍有服务连接记录。
  该记录不等于 CDC 串口读取错误，也不能证明此前首次启动离线的根因。

## 主机修复

配置页分开显示设置值和下载器最后确认的速率。确认未知时显示“未确认”，
不再从已保存的设置推断实际速率，也不把所有失败硬编码成 1 MHz。
连接后修改速率失败会保存警告并刷新状态；再次应用成功后清除警告。
提供重新应用按钮，保留高速精确确认和保守回退要求。

提示不再断言必须升级固件。先检查目标连接；IDCODE 为 0 或全 1 时明确提示
目标尚未识别，应检查供电、共地及调试接线后重连。连接下载器与成功访问目标
分别解释。低速命令也未获确认时清除缓存速率，避免沿用旧值。
