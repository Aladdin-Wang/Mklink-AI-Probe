# 0.3.0 跨进程端口锁收敛

日期：2026-10-03。基于 b2df031，处理架构复审 A7 的稳定锁目录部分。

## 问题与改动

后台为自身配置独立 TEMP，旧端口锁也从 TEMP 派生，导致后台与客户端不能看见同一锁。
Modbus 另有重复的端口锁实现和目录，同一 COM 口在两类客户端间无法通过建议锁互斥。
Windows 的原锁范围还覆盖 PID 的首字节，使其他进程读取持有者失败。

现在 CMD、UART、Modbus 共用 `local_resources._PortLock`，删除两处适配器中的锁实现。
继续使用系统文件锁，没有增加锁服务或任务执行器。默认路径复用平台应用数据目录，
不依赖 TEMP、工程或后台注册目录；显式 `MKLINK_LOCK_DIR` 仅用于统一配置的隔离环境。
单元测试自动使用各自的构建临时目录，避免触碰用户正在运行的端口注册表。

锁文件使用二进制句柄，保留首字节用于系统锁，PID 放在后续字节。资源盘点可独立读取。
进程退出由操作系统释放锁；正常释放清空 PID。清理失效状态时必须先取得同一系统锁，
只清空元数据而不删除文件，避免 POSIX 删除后新旧句柄锁住不同 inode 的问题。
PID 缺失也不能作为端口空闲的依据。强制结束持有者仍要求调用方显式传入 force。

协议升为 7，旧协议后台必须显式退出后升级。新锁不兼容仍在运行的旧 TEMP 锁命名空间；
不自动迁移、终止旧进程或宣称能协调任意第三方工具。按用户要求删除旧全局锁的路径、解析分支、清理函数及 CLI 返回字段；不保留旧锁兼容。
原 CLI 中无连接调用方的进程内串口 dashboard 清理回调也已删除，清理只操作显式端口锁。
下载器 USB 身份、每探针后台隔离、CDC 传输和固件保持原方案。

## 验证

- 修改前新增跨进程测试 **6 项失败**，复现目录分裂及持有者不可读。
- 修改后首批 60 项通过，扩大到共享运行时、身份和 MCP/SDK/CLI 后 134 项通过。
  最终相关回归 **274 项全部通过**，包含资源、Modbus、串口、真实 API、任务、HIL 锁、
  项目交接和 Skill 边界检查。未重跑应用全量或 GUI 全量。
- 真实 Windows 子进程：不同 TEMP/后台目录对同一端口互斥，不同端口可分别持有；
  正常退出和强制终止测试子进程后可重新获取；活跃 PID 可读；PID 缺失仍不能删除活锁；
  失效清理保留 inode；协议 6 后台被拒绝。测试进程不打开物理串口。
- 主 V4 + STM32F103RET6 + 真实 Edge + MCP + SDK：GUI 运行 RTT，独立 CLI 可以读取
  后台 PID，普通 release-serial 返回 live_owner，GUI/MCP 采集继续。
- 使用另一 TEMP 和后台注册目录的子进程尝试 UART/Modbus 同一 CMD 口，均在打开串口前
  拒绝；未向目标发送探测命令。停止采集后 Boot 前 20 KiB 逐字节不变，VTOR 保持
  0x08005000，tick 推进。未复位、烧录、擦除、改时钟或 VCC。
- 第二只下载器重新枚举，未操作其目标；不把不同虚拟端口的锁测试写成双设备长稳。
  测试后台退出后端口锁释放。真实浏览器无 pageerror/HTTP 5xx，截图已检查。

真机验证在统一的 E 盘隔离锁目录执行，后台 TEMP 与客户端仍不同。最终公共模块提取、删除旧兼容后
再次验证相同行为。GUI 未改，使用前轮生产资源；固件、私有设备标识、日志和截图未提交。
构建入口保留的含链接临时目录未强制清理。
