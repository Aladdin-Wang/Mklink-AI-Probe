# 0.3.1 dumpmem 接收积压与时间戳缺口

2026-10-09，用户要求直接依据数据内时间戳判断丢失，并修复上位机队列积压。
本轮正式对照未修改固件或给运行时加诊断钩子，使用既有 measure/capture API。
安装态基线为 acdcc997，修复源码为 77d4849c。相同 V4.6.3 / F103RE、30 MHz SWD、
单个 4B RAM 变量；没有改变 VCC、复位或写入目标程序。

旧计数还包含停止时未消费的尾部，不能把全部字节数换算成采集中的缺失时长。

此前临时源码钩子测得的 5.830 ms 仅保留为探索记录；用户要求不加诊断代码后，
已停止使用该运行方式。这里的安装版对照及修复后结果全部来自正常 API 与数据时间戳。

## 原因与修改

- measure 原来将 MUX 批量样本展开成每点区域对象，再逐点创建 assembler，
  重复处理已经验证完整的数据。改为复用现有 packed 样本，直接统计时间戳。
- capture 原来在接收热路径逐点组装区域、转十六进制并调用 JSON 序列化计算大小，
  有数据时还固定休眠 1 ms。现在先保留有界的紧凑样本，确认停止后再生成 API 输出；
  只有没有数据时休眠。16 MiB 限额通过同等精确的 ASCII 长度计算保留。
- 保留 OLD/B1 的分块、顺序、CRC、区域完整性验证和取消/停止确认。
- measure 与 capture 增加队列字节丢弃失败判断，不能丢了数据仍返回成功。
  此检查包含停止过程，属于保守拒绝；不会把停止尾部丢弃伪装为中间缺口。
- MUX 丢弃统计取本次会话增量，避免历史采集的计数污染下一次结果。

未扩大队列、降低请求采样速率、修改固件批次策略或添加产品诊断代码。
