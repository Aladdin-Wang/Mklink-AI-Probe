## 修复与证据边界

用户补充：CDC 停采发生在 30 MHz、请求 1 µs；后台离线在首次启动出现。
原始记录见 [0.3.2 发布后故障](v032-postrelease-incidents.md)。
本轮没有复现原始 `GetOverlappedResult` 失败，也没有重现用户的首次启动离线，
因此不能宣称两个底层根因已经消除。

已经修复的具体路径：

- Windows 排队读取失败立即保存并上报 Win32 错误码和系统说明。
  非预期错误仍终止接收；只把主动关闭引起的取消作为正常结束。
  接收线程失败后，worker 拒绝后续写入和清缓冲命令，保留原始失败原因，允许关闭。
- SuperWatch 区分界面 WebSocket 与物理设备状态；后端错误和设备断开优先于
  WebSocket connected 状态，不会被后续通道遥测覆盖为健康绿标。
- 桌面健康检查改用 Tauri v2 IPC 查询本窗口端点，修复事件初始化失败后
  永远探测端口 0、或重启后停留旧端点的恢复缺陷。
  原生启动错误及时传到页面，并保留每次启动最多 256 KiB 的代理输出日志。

## 本轮真机结果

用户确认的 V3 + STM32F103 测试板；被动枚举后查询版本为 V3.6.4。
使用用户提供的现有 AXF；未烧录固件、写目标变量或改变供电。
设备身份、工程路径、原始日志只在原工作区忽略的 `.build/artifacts/v033-fixes`。

1. 源码诊断后台与官方桌面，30 MHz、单变量、1 µs，界面改为百万点缓存。
   约 695 秒观察未发生 CDC 读失败；最后记录约 2.069 亿 read cycles。
   read_errors、firmware_read_errors、CRC errors 为 0，但
   `parser_dropped_bytes=11754288`。该计数包含 mux 接收队列溢出丢弃；
   期间同时执行本机构建和测试，不能据此断言因果，也不能称为无损采样通过。
   这次后台尚未加载最终 worker 防护，不代替候选验证。
2. 最终冻结候选，30 MHz、单变量、1 µs，90 秒约 2371 万样本，
   实际速率约 261–265 kHz，读错、CRC、固件读错和丢弃指标均 0。
   浏览器后半段订阅，期间缓存从 5 万改为百万点；不冒称全程百万点或 1 MHz 实测速率。
3. 对本次候选的独立接收 worker 注入进程退出：采样停止，设备断开，
   Web 明确显示 `界面通道 connected · 设备未连接: Serial worker pipe closed`。
   这是进程退出注入，不能替代原始 Win32 失败复现。
4. 显式重连、重载 AXF 并重新选择变量后恢复约 261 kHz 采样，错误清除，
   read cycles 继续增加；再正常停止并断开，页面显示设备未连接。
   重连后未选变量时允许空闲运行，不能用 running 字样单独判断有采样。

自动化工具曾返回缓存的旧端口文字，实际原生截图已显示新端口；
不把该工具缓存现象登记为产品缺陷。

## 遗留与继续条件

- 原始 CDC 失败仍待在同一条件下复现并取得新的 Win32 错误码；
  不能把 V4 已知目标 status5 问题当成本次主机读错误。
- 首次冷启动离线仍待复现；新候选将提供启动退出原因及日志路径。
  本轮普通启动成功与故障注入恢复不证明原始首次启动问题彻底修好。
- 用户暂缓实际覆盖安装；后续授权实装后再核验安装态首次启动。
- Windows 本地包未签名；Mac/Linux 本轮未重新构建或真机验证。
- 运行包装器因测试创建的链接保留了三个临时 run 目录，未强删；
  精确本地路径保存在原空间的回归记录中。正式 0.3.2 归档未改动。
