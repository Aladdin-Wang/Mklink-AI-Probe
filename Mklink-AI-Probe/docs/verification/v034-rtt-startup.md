# 0.3.4 RTT 启动与共享采集修复

日期：2026-10-11。分支：`codex/0.3.4-fixes`，基于 `271af444`。
本报告是开发分支验证，不是正式版本发布或客户现场根因闭环。

## 客户证据与结论

两位客户的内存截图都显示 `SEGGER RTT`。第二位的读指针大于写指针是合法环形回绕，不能据此判定控制块损坏。第一位截图未覆盖完整描述符表，不能确认整个控制块有效。

客户提供的 AI 记录显示：11.12 秒尚未返回控制块地址，18.29 秒就绪；随后发生 `Multiplex response timed out; outcome unknown`。这说明启动等待与运行时通信失败需要分别排查，不能把整个 18 秒归因于 1024 字节扫描，也不能把超时直接解释为地址错误。

代码与复现实验确认以下主机侧问题：

- 每次检查控制块、描述符和缓冲区都可能重复完整 ELF RAM 范围解析。同一启动可解析 13–15 次。
- 即使提供准确的控制块地址，也先读整个扫描窗口。
- 发现签名但描述符不在可信 RAM 范围等原因被丢弃，最终只报“找不到控制块”。
- RTT / SystemView 界面分别只等待 11 / 8 秒；RTT 还把启动超时提示为地址问题。
- RTT 原始错误在阻塞清理结束后才发布，状态查询也等同一 I/O 锁；SuperWatch 的清理异常会掩盖采集异常。
- 唯一串口读取线程在接收已排队响应前检查 MUX 截止时间，调度暂停后可错误判超时。原诊断没有失败请求身份。
- 真浏览器复核发现 SystemView 承诺确认后自动停止 RTT，与共享后台禁止抢占的规则不一致。

## 最终实现与架构边界

可信 RAM 范围通过 `ContextVar` 保存在单次调用上下文中，嵌套校验复用；退出后释放。不同线程隔离，每次新启动重新解析，未增加跨启动持久缓存。原有可信 RAM、对齐、长度、通道、描述符和返回地址校验继续生效。

动态搜索先验证指定地址，失败后才扫描原有有界窗口；只保留实际观察到签名的拒绝原因，传输失败立即传播。新增 RAM 边界、映射变化和线程隔离回归。

RTT 与 SystemView 使用统一 60 秒后台准备等待上限。设备通信仍使用原来的短截止时间，不重试未知结果。RTT 暴露准备耗时及 RAM 解析、传输准备、控制块校验、探针启动阶段耗时；SystemView 底层返回 RAM 解析和总耗时。

RTT 状态读取使用一次性发布的启动快照，写入、停止及工作线程所有权仍由原锁管理。RTT / SuperWatch 提前报告原始错误，清理结束前仍保持工作线程占用；二次清理错误不会替换原始错误。

MUX 仍只有一个串口读取者，先解析本次读到的数据，再执行超时/心跳检查。心跳写入仍在串口故障处理边界内。超时保留 opcode、request、epoch、心跳标记、超期时长、最近接收/应答时间和未解析字节数；真实丢失响应仍失败并禁止重放。这只消除已排队响应被提前判超时的路径，不保证解决所有主机停顿、链路拥塞或固件故障。

SystemView 遇到采集冲突明确要求先停止原会话，不改变共享后台订阅、资源互斥、设备身份、操作锁或固件所有权。

### 固件核对与真机

V3 / V4 当前源代码的 `rtt_channels.c` 分别编译运行截图布局夹具，返回 6 / 228 字节；核对 MUX 心跳、目标操作准入、USB 收发与所有权路径。未修改或升级下载器固件，固件夹具不计为实体 V4 验证。

实体环境为 V3.6.4 + STM32F103，Windows 源码共享后台与生产 Web。用户明确授权使用和修改测试工程；供电未改动。

- 原 8 通道测试程序：5 次 RTT 启动 0.202–0.334 秒；8 通道 RTT + 3 变量 SuperWatch（1 ms）+ 第二客户端内存读取连续运行约 126 秒，采集持续、SuperWatch 读错误为 0。验证第二客户端不能重配置现有采集、有其他订阅者时停止被拒绝，退出订阅后可以正常停止。
- 工程已有 SystemView 测试开关生成的镜像：通过共享烧录任务烧录、校验并复位。3 次 SystemView 启动 0.532 / 0.552 / 0.656 秒，每次持续 15 秒，分别解析约 12.3 万事件。
- 真浏览器：RTT 实际日志持续增长；SuperWatch 显示正弦/三角测试波形；SystemView 冲突提示与显式停止后的启动均通过。Trace 页面确认 13 个任务、72 MHz、331969 个事件、Runtime Drop 0，浏览器错误日志为空，最后停止并关闭测试页。
- 最终后端故障处理边界调整后再次冷启动：RTT 0.328 秒就绪，20 秒仅状态查询期间心跳保活正常；随后 30 秒并行 Watch/内存读取，35209 个 Watch 周期、读错误 0；SystemView 0.354 秒就绪、15 秒接收 123150 个事件。停止后资源为空、共享后台退出。结果见本地 `final-hardware.json`。
