# 0.3.1 Skill 与 GUI/AI 控制权恢复

日期：2026-10-08。分支：`codex/0.3.1-fixes`，PR #33。

## 客户反馈与已确认原因

客户使用 DeepSeek 时经常与 GUI 争用 MKLink，关闭 GUI 后仍无法恢复，曾只能重启电脑，
并称 AI 无法结束占用进程。尚无客户的持有者 PID、结束进程系统错误及任务状态，不能
将全部现象归因于同一个缺陷，也未在客户电脑复现。

代码确认两个恢复障碍：

- GUI 创建的采集没有客户端 owner 项；`require_acquisition_control` 将其永久当作 GUI
  所有，即使最后窗口退出也拒绝唯一 AI 订阅者停止。该 AI 的续约使后台仍然存活。
- MCP `runtime_status` 原来依赖已建立的客户端对象和缓存端点，连接失败时不能独立
  查看占用；管理操作只有 GUI HTTP 入口，AI 缺少对应的类型化 MCP/CLI 工具。

Skill 还将超时恢复过早收束到断开重连/拔插，缺少会话、操作系统串口持有者、目标调试
所有权的区分；旧说明仍要求下载前手动停止所有采集，与本分支下载修复不一致。

## 改动

GUI 所有窗口和远程使用者离开后，唯一已订阅客户端可显式接手停止/暂停遗留采集。
其他订阅者、活跃本地窗口和远程连接继续受保护；不自动重启或重配采集。
状态新增采集 owner 的类型、是否仍在场和客户端公开管理 ID，不泄露会话密钥。

`runtime_status(probe=...)` 按稳定身份重新查找现有后台，无需连接设备，不启动后台。
新增 `runtime_control` 和 CLI `runtime control`，复用既有管理准入：结束指定会话、
停止指定采集、释放设备、退出后台。修改要求 `confirm=true`；拒绝仍在执行的任务
及其他使用者冲突，不支持强杀、不绕过串口锁、不重放失败命令。正常收尾仍是 disconnect。

Skill 入口保持 4500 字符以内，详细流程收敛到 `references/runtime-recovery.md`。
安装、共享运行时、GUI 及工作流说明同步，强调旧后台/MCP 进程不会随文档更新自动替换。

## 验证

- 最终同一批 364 项通过：共享运行时/VOFA、MCP、CLI、UART、空闲退出、真实进程退出、
  重连、任务、下载暂停恢复、窗口登记、发现、启动、桌面代理、反馈契约及 Skill 边界。
- 覆盖 GUI 主动释放、5 秒存在性过期、WebSocket 窗口关闭；另一订阅者/远程用户保护；
  未订阅者不能接管；已撤销会话心跳拒绝；MCP 未连接时查询和管理；显式选择其他后台
  不改变原选择；错误管理参数不访问后台。
- Windows 真实无硬件后台进程：经新控制入口查询 PID/会话，停止后进程退出且实例锁
  可重新取得；覆盖断裂/保持连接的流客户端。此项不代表真实串口或 MCU 恢复验收。
- Skill quick_validate 通过；公开包链接/上下文边界通过。初次测试的 WebSocket fixture
  Host 与后台不一致、入口文档超长均已修正，最终批次全部通过。
- 唯一警告为既有 websockets.legacy 弃用提示。构建包装器因测试链接保留本批临时目录
  `.build/runs/run-20261008-222720-bb38253e`，未强制删除。

本批只改后台、工具与文档，无 GUI 页面改动。未构建新 NSIS，未覆盖本地或客户 Skill，
未操作探针硬件。旧 connection-fix 本地安装包不含本批与上一批下载修复。
下载器固件及实机继续由用户指定会话负责；客户“杀不掉”的系统错误及 CS32L015 场景
仍需对应环境验证。另行排队的 RTT 假签名搜索问题未在本批修改。
