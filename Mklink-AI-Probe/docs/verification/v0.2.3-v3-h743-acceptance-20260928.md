# V3 / STM32H743 功能验收与 USB 异常记录

## 范围与结果

真实 V3、STM32H743、现有目标程序，通过桌面同一套 FastAPI 后端和实际 HTTP/串口验收。不是模拟设备；未做浏览器视觉验收。客户另行反馈 H563 AP 修复验收通过，该结果不作为本地 H743 的替代证据。

最终一轮完整通过：

- 首次 Memory 读取测试数组 4096 字节，与程序初始化图样逐字节一致。
- 非对齐读取 4095 字节，覆盖 1 KiB TAR 自增边界；Flash 前 256 字节与目标 AXF 一致，CPUID/DHCSR 可读。
- Memory → SuperWatch → Memory：1364 个完整样本。
- 目标软件复位 → 直接 SuperWatch → Memory：新增 1420 个样本，无 Memory/CLI 预读。
- 断开/重连 → 直接 SuperWatch → Memory：新增 1356 个样本，无 Memory/CLI 预读。
- 三阶段共 4140 个样本，读错误、读丢弃均为 0；16 元素数组内容正确，采样序号、时间戳增长，停止后完整 RAM 回读一致。
- 专用测试数组中非对齐 47 字节写入、全零写入、回读及恢复通过；最终完整 4096 字节匹配原图样。

目标程序、Cache、变量位置均未修改，未调整供电。软件复位测试不能代替物理断电测试。未在本轮重新刷探针固件，版本号不足以证明运行二进制与本地构建逐字节相同。

## 验收中修复的主机解析错误

首次写入 `00 01 ... 2E` 后，47 字节只解析出 31 字节。固件每次输出一行时间戳/列标题；主机错误地将后续内容恰为 `00 ... 0F` 的 RAM 数据行也跳过。

修改普通内存和带时间戳的兼容读取解析器：只在数据开始前识别一次时间戳表头，保留后续同值数据行。二进制 SuperWatch 采集不经过该文本解析器。

7 项针对性测试覆盖首行/后续行冲突、重复图样、全零及旧式表头；连同内存完整性、调试控制、RTT/SuperWatch 相关回归共 98 项通过。修复后上述真实硬件整轮通过。修改仅进入 0.2.3 开发源码，安装包尚未重建、未发布。

## USB 稳定性仍待解决

之前一轮重连采集约 149 帧后停止，退出流无法恢复命令模式，随后两个串口和存储卷消失。用户确认未拔插；仅重新插拔无法恢复，卸载 CMSIS-DAP 设备节点后插拔才恢复。Windows 安装日志记录节点删除成功，不能据此声称删除了驱动包或驱动损坏。

一次恢复后 PnP 显示 OK，但串口配置返回 Windows 433（指定不存在的设备）；该次尚未发送目标识别命令。再次人工恢复后，本报告最终轮通过。

V3 源码审查发现：

1. 看门狗实际为 10 秒，由变量采样线程每轮结束后刷新。尚无本次复位原因，不能确认看门狗触发。
2. `chry_dap_handle` 在整条 `DAP_ExecuteCommand` 外关闭全局中断，WAIT/匹配重试会延长 USB/调度阻塞，USB Abort 也无法在关中断期间到达。
3. USB RESET 处理没有重置 DAP 的请求/响应索引、计数；CONFIGURED 固定把接收挂到 `USB_Request[0]`，而回调读取当前 `USB_RequestIndexI`。历史索引非零时存在不一致风险。
4. DISCONNECTED 处理为空；控制台复位时未完整清理发送队列与会话状态，需连同在途传输一起审核。

这些是代码风险，尚未用可控复现实验证明本次根因。本轮仅完成 AP/Memory/SuperWatch/写入功能验收，不宣称 USB 长期稳定性通过。后续针对用户报告的连续芯片识别失败条件，记录 USB 故障码、复位原因和时序，再验证恢复修复；不以延长/关闭看门狗代替定位。

原始脚本、各次失败记录和最终 results.json 保留在本地目标工程的 `.mklink/ap-h743-20260928`，不提交硬件标识和二进制。
