# 0.3.1 上位机连接恢复

日期：2026-10-08。分支 `codex/0.3.1-fixes`，PR #33。仅修改上位机；下载器固件由用户指定会话 `01a11b6a-0a88-73a0-b6f7-919ab7454c92` 处理。本会话 `01a11b53-dbcf-7830-aac0-2d4a6ad5bf77` 不竞争其测试板、串口或调试器。

## 原因与改动

- MCP/SDK 的 `RuntimeClient` 缓存后台地址，重新 `connect` 仍向旧实例附着。明确连接时现在先检查实例；后台失效或实例变化后按原下载器身份重新发现。旧 session 不发送给新后台，旧续租线程固定使用自己的地址快照。普通读写和独占任务不自动重试。原设备缺失时不转向其他设备。
- USB 拔插后旧串口句柄仍需关闭，而旧客户端心跳原来会无限续租。目标连接失效、设备缺失或换端口后，空闲状态的目标租约会被撤销；独立 UART 租约保留。进行中的任务/连接事务可以暂时关闭 CDC，此时不误撤销租约。
- GUI/MCP 明确重连同一 USB 身份时可以处理换 COM 号，先停止旧桥采集、关闭旧句柄，再撤销旧目标会话并打开当前端口。旧客户端必须重新附着，不能沿用旧会话执行新连接上的命令。后台的操作锁和独占任务保护继续有效。
- 健康连接仍被其他客户端共享时，GUI 的“断开”保留保护，但返回公开的占用客户端列表。配置页显示占用者，并提供“打开后台管理”入口，使用已有的显式结束会话功能；不会自动逐出其他客户端。
- 串口连接失败保留锁占用、串口打开异常、提示符超时等原因。配置页保留用户明确选择的端口，重试不会悄悄变为自动搜索。
- 固件会话实测 Keil Debug+Run 时，RTT 遇到 MUX status 6 后 SuperWatch 报 Device not connected。主机根因是 `bridge.enable_multiplex` 在 HELLO/CLAIM 成功后，仍将可选 SWD attach 的目标拒绝混入协议握手失败，调用 `transport.fail`。现分开这两个阶段：有效目标响应不毒化 CDC；可选初始化 busy 保留已 claim 的协议，后续目标请求仍须固件准入。普通读写的 busy 明确报错且不重放，CRC/epoch/超时/不完整写仍使会话失效。固件同时维护旧主机兼容的幂等 attach，源码方案已双方核对。

## USB 身份与命令握手

发现设备使用 USB VID/PID、命令接口 `MI_04`、序列号；COM 编号仅为当前端口位置。发现过程不打开串口、不访问目标芯片。重复或缺失序列号不会合并成同一稳定设备。

普通连接在收到命令提示符后，已知 USB 命令接口本来就跳过 `print('__mklink_probe_7f3a__')` 查询。但 SystemView、文本流和 MUX 恢复成功后，旧代码仍执行该打印。固件把非白名单脚本归入目标调试仲裁，可能把这条无目标访问的身份打印拒绝为 DAP busy。

本次三个恢复分支也按 USB 元数据识别已知命令接口，不再发送多余身份脚本。仍需确认提示符或协议 EXIT 应答，不能仅凭 COM 存在就假设通道已经退出流模式、可以接收命令。未知接口的兼容路径仍校验响应，目标 SWD 初始化仍与身份识别分离。固件侧只读命令白名单由指定固件会话维护。

另有失败流停止后的 token 往返用于排空迟到的停止应答，属于协议同步屏障；USB 枚举无法替代这种有序确认。本轮保留该屏障，固件侧须允许其不可变只读实现，不争用目标调试锁。
