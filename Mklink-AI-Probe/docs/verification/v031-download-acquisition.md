# 0.3.1 下载期间自动暂停与恢复采集

日期：2026-10-08。分支 `codex/0.3.1-fixes`，PR #33。源码 `7b9c87a8`，生产 Web 资源 `b91acb92`。仅修改上位机；未合并、发布、覆盖安装或操作实体探针。原有 connection-fix 本地 NSIS 不包含本批改动。

## 原因与行为

共享后台原先在请求入口拒绝任何仍有 RTT、SuperWatch、VOFA、SystemView 采集的在线/脱机操作。在线页面在发送前保存凭据，却把明确的入口拒绝和响应丢失都当作结果未知，导致截图中的待确认面板和人工结束跟踪。

- 在线后台任务、MCP/CLI flash、脱机部署/算法拷贝/触发及在线内存读取现在临时停止冲突的桥接采集；独立 UART/Modbus 不受影响。
- 保存原启动配置、暂停状态、RTT 通道编码、VOFA 当前采样周期及 SystemView 录制状态。保留共享订阅和创建者，不把临时停止当作用户断开；SystemView 恢复录制会开启新日志段。
- 在运行时准入和桥接生命周期锁内完成暂停，确认工作线程退出、释放资源后才开始下载。部分停止失败会回滚已停止通道；仍存活的线程不会获得第二个读者。
- 在线任务的整个后台执行及清理期间保留独占任务记录，完成、失败或用户停止后均尝试恢复。HPM/断电复位关闭 CDC 后只按原 USB 身份重新打开连接，不切换探针，不重放烧录。
- 脱机/读取的最终响应片段等待恢复结束；进度继续流式发送。采集恢复失败单独进入结果和运行时状态，页面展示该错误，不覆盖实际烧录结果。
- 后台显式标记 `X-MKLink-Submission: not-started`，只有明确未接收的请求才自动清除凭据。桌面代理允许 WebView 读取此响应头，脱机请求头和表单凭据必须一致。网络异常、未知结果和已有任务继续通过原凭据查询，不自动再次写入。
- 正常运行时隐藏恢复面板，已接收任务自动查询到终态并清除凭据。轮询不会反复重建日志订阅，也不会用滞后快照把已观察到的终态改回运行中。
