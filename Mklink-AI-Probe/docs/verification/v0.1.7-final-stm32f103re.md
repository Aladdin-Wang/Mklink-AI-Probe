# v0.1.7 final release-candidate qualification

Date: 2026-08-24

Source: `master` at `0b1cf5109315203f0e0a0596d35bc78f4e051ca8`

Decision: the local v0.1.7 release candidate is qualified with the limitations
below. No functional release blocker was found in the exercised build, GUI,
installer, or STM32F103RE hardware paths. This qualification does not create a
tag, GitHub Release, or updater manifest.

The fixture directory retains its historical `STM32F103RC` name, but the
physical MCU, Keil device, online-flash target, and this report all use
`STM32F103RE`.

SystemView attached to an intentionally high-rate test stream and reported an
existing target-side overflow baseline. It decoded the live stream correctly,
but target events already lost before transport cannot be reconstructed. This
is retained as a load limitation, not hidden as a clean zero-loss claim.

## GUI and installed runtime

The source-served GUI loaded without console warnings or errors, displayed
`v0.1.7` and the source commit, connected the physical target, navigated the
dashboard/offline/online views, indexed the installed device catalog, and
loaded the exact STM32F103RE configuration.

The NSIS candidate installed silently with exit code 0 and registered version
0.1.7. Its packaged sidecar became healthy, had no Python descendant process,
connected the physical target, loaded the AXF with the builtin ELF backend,
and read the `20260824` identifier from target RAM. Closing the desktop window
stopped the application and sidecar and released the API port. The candidate
remains installed for maintainer inspection.

Windows desktop accessibility automation was unavailable on the qualification
host. The desktop window was nevertheless confirmed responsive, while its
shared frontend was interactively exercised in Chrome and its packaged
backend, process tree, target connection, symbol loading, RAM read, and
lifecycle were independently checked.

## Not established in this fixture

- Real serial TX/RX was not claimed because no verified UART loopback or peer
  was identified.
- Modbus RTU was not claimed because no verified RS-485 slave or simulator was
  identified.
- Probe VCC was not enabled because no exact voltage was authorized.

These items require their external fixture or explicit voltage confirmation;
automated coverage is not substituted for a physical PASS.
