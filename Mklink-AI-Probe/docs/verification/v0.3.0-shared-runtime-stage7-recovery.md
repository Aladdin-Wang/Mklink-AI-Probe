# 0.3.0 第七阶段：WebGUI 连接恢复

日期：2026-10-03。接续 `96681d4`，分支 `codex/v0.3.0-shared-runtime`，草稿 PR 30。
按计划在桌面安装验收前，继续验证 WebGUI。使用当前源码独立生产构建、真实 Edge、
真实 MCP 进程、SDK 和主下载器；本轮只枚举到一只设备，双设备证据仍以第六阶段为准。

## 修复

- 原页面在后台失联后保留视图，仅状态栏变为离线，容易把旧数据当作实时数据。
  现在页面顶部明确提示连接中断及数据状态，保留视图供查看。
- 健康检查区分 HTTP 401 与网络不可达。后台重启更换授权后，旧页提示授权失效，
  指引按原下载器 ID/别名重新运行 GUI 并打开新链接，不自动授权或选择其他设备。
- 浏览器初次连接失败时提供“重新检查”，不再显示无法启动本机进程的“重启服务”。
  桌面原生重启入口保留。

## 验证

| 检查 | 结果 |
|---|---|
| GUI 全量 | 775 项通过、75 个文件；新增首次 401、在线/断网/401/恢复、保留视图和浏览器检查入口用例 |
| 构建 | Vue 类型检查和独立目录生产构建通过；跟踪的 gui/dist 未改 |
| 浏览器短暂离线 | Playwright 将该 Edge context 切到 offline，页面显示连接中断；后台 RTT 继续，另一个实际 MCP 进程可读取历史 |
| 同实例恢复 | context 恢复 online，健康提示自动消失、RTT 页面仍显示采集、后台仍在运行、MCP 可继续访问 |
| 后台正常退出后重启 | 先结束测试会话及采集，正常停止本次后台，在同一端口重启；实例 ID 改变，旧页面收到 401 并显示重新打开指引 |
| 不隐式重连 | 新后台仍未连接设备，RTT 未启动；旧页面“重新检查”未改变此状态 |
| 显式恢复 | 打开新授权链接、通过页面快捷连接原下载器、在文件来源输入原 AXF 并解析，页面显示符号已加载，SDK 指定相同 AXF 后附着成功 |
| 目标完整性 | 完整 20 KiB Boot 区前后逐字节一致，VTOR 为 0x08005000，RT-Thread tick 递增 |
| 浏览器诊断 | 最终流程无 pageerror、无 HTTP 5xx；授权失效与恢复后截图已目视检查 |

首次脚本假定后台进程重启会保留 SDK 临时指定的 AXF，因符号不同收到正确的 409。
第六阶段的“恢复上次 AXF”仅覆盖同一进程内释放后重连。修正验证流程，在新页面
显式加载并核对 AXF 后完整通过；没有放宽符号冲突检查，也没有新增自动恢复硬件操作。
该区别已补入使用说明。健康提示恢复不代表采集数据无损，本轮没有做流丢包计量。

本轮只修改前端及文档，未重复 Python 全量；后台回归沿用第六阶段 92 项、第五阶段
全量 2553/3 跳过的历史证据。既有 Node localStorage 实验性提示与生产大 chunk
提示仍在。测试客户端、采集和后台均已停止，未烧录、擦除、修改 Boot/App 或下载器
固件，未改变 VCC。设备标识、路径、截图、日志及构建资源只保留在忽略的 .build。

## 边界与后续

本轮覆盖浏览器可达性中断与空闲后台正常退出后的重新启动，不代表进程被强杀、
操作中 USB 拔插、睡眠唤醒或 24 小时长稳已经通过；也没有重复双设备或安装升级。
继续完成专用 CLI/低层调用迁移、全新连接擦除准备与脱机部署，并验证操作中断和
持续运行，再进入 NSIS 安装升级。保留 Bootloader 与 0x08005000 App 布局，
开发版本不自动合并或发布。
