# 0.3.0 第六阶段：先验证 WebGUI

日期：2026-10-03。接续 `fcf304b`，分支 `codex/v0.3.0-shared-runtime`，草稿 PR 30。
按用户要求先验证 WebGUI，桌面安装包/升级留待后续。本轮从当前源码构建独立
生产资源，用真实 Edge 浏览器、真实 MCP 进程、SDK 及下载器验证页面交互。

## 发现与修复

1. **RTT 停止被拒绝时，页面错误地断开显示。** GUI 与 AI 共用采集时，点击停止
   正确收到后台 409，但前端已断开二进制流并切成“重试”。现在只在后台接受停止
   后清理显示；拒绝时保留运行/本地暂停状态、流连接及停止入口，同时显示原因。
   还限制同一窗口重复提交正在执行的停止请求。
2. **共享后台快捷重连丢失符号配置。** 为防旧 COM 口覆盖 USB 身份，原实现把
   restore_last 整体关闭，导致释放后 GUI 重连没有保留 AXF，SDK 再附着报符号
   不一致。现在端口仍按绑定 USB 身份解析，只在重建连接时恢复上次 AXF、芯片
   和 ELF 后端；已连接的设备复用当前符号，不因隐式连接重新解析。
3. **释放后的页面状态滞后、采集忙提示不明确。** 后台管理释放成功后立即刷新
   共享设备状态，快捷按钮及时变为连接；内存页收到结构化采集冲突时显示采集名称
   和停止路径，不再只显示 Conflict。

## 最终验证

| 检查 | 结果 |
|---|---|
| GUI 全量 | 771 通过，75 个测试文件；覆盖停止拒绝、保留暂停状态、重复提交、错误提示及释放后状态同步 |
| Web 构建 | Vue 类型检查、独立目录生产构建通过；未覆盖跟踪的 gui/dist |
| Python 受影响范围 | 92 通过：设备 API、共享准入、SDK；新增恢复符号但不恢复旧 COM、拒绝其他探针、复用现有符号测试 |
| 双窗口与 AI/SDK | 同一后台列出两 GUI、MCP、SDK；有其他会话时，页面释放/退出请求显示拒绝 |
| Memory | 页面读取 App 向量与 SDK 一致；RTT 运行时读取返回 409，显示可理解的提示，采集继续 |
| RTT | 页面启动后 AI 订阅；GUI 停止被拒绝后仍显示运行。关闭一个窗口不影响后台/AI，另一窗口刷新后继续显示采集 |
| 会话管理 | 页面结束指定 AI 会话后，可停止该采集；未误停其他客户端或直接释放整个设备 |
| SuperWatch | 页面添加 rt_tick、启动采集，实时值持续变化并显示曲线；SDK 可订阅；GUI 停止被拒绝后保持运行，SDK 退出后显式停止成功 |
| 释放与重连 | 页面释放、快捷重连、SDK 再附着成功；原 AXF 保留，物理探针仍由稳定身份选择 |
| 磁盘与退出 | 页面 USB 磁盘核对成功，最后通过“退出后台”显式停止，页面显示已退出 |
| 真实浏览器 | 最终完整流程无 pageerror、无 HTTP 5xx；RTT、SuperWatch、Memory 和管理页截图已目视检查 |
| 双物理探针 | 用户换入新的第二只后重新识别；两个后台 PID/端口/工程/卷 GUID 不同，两个窗口只显示自身客户端，结束第一只 SDK 不影响第二只，多探针不指定设备时拒绝连接 |
| 目标完整性 | VTOR 保持 0x08005000，完整 20 KiB Boot 区前后逐字节一致，RT-Thread tick 递增 |

首次脚本复现 RTT 显示问题；之后从管理页切回仪表盘时，测试脚本改用实际页签按钮，
避免把已保留的仪表盘误当作重新挂载。该测试不认证已挂载页面的 query 参数导航。
受影响 Python 测试第一次命令含不存在的测试文件，修正清单后实际执行 92 项通过。
第二只探针曾在用户更换过程中消失；按新身份重枚举并完成双设备验证，没有用旧
序列号或“列表第一台”代替它。

前阶段 Python 全量 2553/3 跳过是历史证据；本阶段新增后端修复以 92 项定向回归
及真实 WebGUI 重连验证为准，未重复全量 Python。既有 Node localStorage 实验性
提示、Web 大 chunk 提示及含测试链接目录保留提示仍在。

本轮未烧录、擦除或改动 Boot/App 固件、下载器固件与 VCC；第二只只做连接、状态
及磁盘身份查询。全部测试客户端、采集和后台已停止，私有路径、设备标识、截图、
日志及构建资源只保留在忽略目录。

## 验收边界与后续

本轮通过的是共享连接、RTT、SuperWatch、内存快照、会话管理、释放重连和双设备
隔离等核心 WebGUI 流程。尚不代表全部页面、全部芯片、物理拔插中断、休眠恢复、
24 小时长稳或桌面安装升级通过。未重复真实 Flash/erase、HardFault 故障注入、
串口/Modbus、RTOS Trace 事件及下载器升级验收。

继续按计划完成专用 CLI/低层调用迁移、全新连接擦除准备及脱机部署，并补齐 Web
异常恢复/持续运行验证，再进入 NSIS 安装升级。保留 Bootloader 与 0x08005000 App
布局；当前仍为开发草稿，未合并或发布。
