## 架构决策

- Remote field machines run only the standalone Site Agent. Engineer machines use the Skill, SDK, remote CLI, or optional remote MCP over authenticated direct ws/wss or managed LAN/VPN transport.
- Non-loopback remote listeners require explicit --allow-lan and token configuration. Tokens come only from environment variables or owner-only files, and local operator confirmation remains mandatory for flash, erase, writes, activation, and Agent stop.
- LAN STCP uses the pinned in-process library bridge. No frpc/frps executable is launched or packaged, and tunnel, Site Agent, and local confirmation credentials remain distinct.
- Any combined-runtime change after the fork's ddf7ff27 qualification invalidates its deterministic package hashes and HIL verdict for release purposes; the integration branch must be rebuilt and requalified before merge or publication.
- The source Vite development server must proxy both REST /api traffic and binary /ws WebSocket upgrades to the same local backend. Any new browser transport prefix requires an explicit development-proxy contract test so source-Web behavior cannot silently diverge from the bundled backend surface.
- AGENTS.md and the repository maintenance Skill are authoritative. Before changing a product, interaction, architecture, workflow, or testing strategy, present the problem, options, tradeoffs, recommendation, and acceptance criteria, then wait for explicit maintainer confirmation. Confirmed-strategy root-cause fixes may proceed directly. Runtime changes require a fix/feature branch, full Python and GUI suites, production build, git diff check, project-memory update, and affected real-hardware loop. Never infer authority to commit, merge, push, sign, tag, publish, modify latest.json, or synchronize Gitee.
- HPM targets always use the dedicated ROM API and never FLM. Agent-driven download routing is IDE-native build/download, then pyOCD online flash, then MKLink offline deployment; do not silently switch after a started operation fails.
- Builtin pyelftools is the default ELF/DWARF backend. External GNU tools run only when explicitly selected. _SEGGER_RTT in ELF/AXF is accepted only when its complete storage lies in an allocated writable section.
- Symbol reload is one shared backend transaction bound to the current Device. Requested and active paths must match, and SuperWatch must be stopped/rebound/restarted serially. Pasted C layouts remain bounded and fingerprint-scoped.
- Large arrays page by 256 direct elements, represented as explicit [start..end] range nodes that load only when expanded. Paging is recursive for structure and nested arrays. Exact search resolves unloaded paths through the backend, and dynamically resolved descriptors remain valid for SuperWatch, type lookup, and read/write. Do not restore a first-256-readable-leaves limit or its UI warning.
- Dashboard sessions and one-shot debug/flash operations use serialized resource leases. User operations may preempt Dashboard owners only after synchronous stop succeeds; one user operation never preempts another. HPM online flash also closes the shared CDC Device before opening its ROM-API backend.
- Desktop and Web-entry clients stop only backend processes they created and still own. Web app shells use no-store, hashed assets may be immutable, and copied user-level Skill/runtime installations must not depend on the development checkout.
- SuperWatch uses a fixed-duration timeline independent of history capacity, defaults to zoom 2 at the newest window, and supports up to 1,000,000 points/channel with a 48-byte-per-point memory estimate and a warning above 512 MiB. Live horizontal interactions preserve the chosen time lag and span while advancing; pause freezes the complete frontend history and viewport; resume clears the snapshot; double-click restores the newest default window. VOFA retains its adaptive timeline.
- SuperWatch effective rate counts complete sample rows rather than variables and never uses the requested interval as the result. The backend uses a one-second perf_counter window as the authoritative status value; the binary viewer uses producer batch timestamps over at least 0.5 seconds for responsive updates between status polls and resets the statistic at stream/layout boundaries.
- SuperWatch defaults to one shared plot. One visible channel may move to a lower plot with an independent persisted Y range while both plots share X navigation. The auto-hiding legend uses a compact reveal button, and a persistent split divider names the independent channel and provides Merge.
- The global GUI language defaults to Chinese and persists under mklink_lang. English technical product names are not translated. Post-flash reconnection was explicitly canceled and must not be inferred.
- RTT View is intentionally fixed to channel 0 with a compact 日志 | 终端 mode switch. Terminal mode uses xterm.js with convertEol enabled so bare LF and CRLF are both display newlines, common ANSI parsing plus SEGGER macro normalization, retained history while hidden, and keyboard forwarding through the existing Down Buffer API. Backend and Log-mode bytes remain unchanged. Do not add termios, PTY/ConPTY, multi-channel UI, or SEGGER virtual-terminal support without a new confirmed strategy.
- Serial Assistant is independent of MKLink deviceConnected and uses the SERIAL_PORT resource while RTT uses MKLINK_BRIDGE/TARGET_DEBUG. Immediate raw serial chunks feed the terminal without waiting for LF; structured events remain parallel for Log mode. The terminal displays RX only and forwards raw keyboard bytes without local echo. Mode/tab/route changes preserve the backend session and close only the browser subscription; explicit Close Port is authoritative. Serial transmit settings/history remain separate from RTT. Physical UART and Modbus access to one COM port must still fail clearly rather than run concurrently.
- Starting or stopping an MKLink-dependent Dashboard never owns the shared Device lifetime. The persistent Dashboard header Connect Device / Disconnect control is the authoritative normal Web owner: Connect restores the last successful actual probe port, AXF path, MCU hint, and ELF backend; Disconnect synchronously stops only MKLink-dependent Dashboards, releases their logical leases, and closes Device. Serial Assistant and Modbus remain independent and are never stopped by Device Disconnect. Dashboard tab, route, mode, and stream-subscriber changes remain non-owning.
- Contextual setup guidance appears where work is blocked and offers the next useful action. Device-only tools prompt quick connect; RTT and RTOS Trace offer AXF/ELF loading for RTT address discovery; SuperWatch and Symbols distinguish missing, stale, empty, and failed symbol states; HardFault keeps symbols optional; RTOS Trace keeps offline JSONL replay available; Serial Assistant and Modbus guide missing serial-port setup without depending on Device.
- Offline Flash serializes only algorithms referenced by firmware rows. Unused unavailable FLM candidates must not block deployment; a selected unavailable candidate must be visibly actionable through local replacement or another algorithm, and backend text remains available under technical details. RTT View and Serial Assistant default to Terminal mode. External documentation/store links display labels only and open with target=_blank plus noopener noreferrer. Family-level MCU IDCODE matches must not claim uncertain density/package qualifiers.
- Windows serial advisory locks always lock byte zero and clear their PID marker before unlock, so repeated open/close cycles do not raise and released resources are not reported as live. Modbus Dashboard opens through ModbusClient.open and returns HTTP 409 when the requested serial port is busy or unavailable.
- RTT View and RTOS Trace share one valid RTT address. SystemView uses SystemView.start plus the SEGGER recorder handshake and matching stop sequence on both ARM/SWD and HPM RISC-V/JTAG. START supplies INIT/SYSDESC/SYSTIME, delayed TaskList recovers startup metadata, ram_base=0 and id_shift=0 are valid, and late attach hydrates task, ISR, clock, drop, and recording metadata from backend status.
- SystemView uses complete bounded intervals for exact Runtime/Context analysis, retains inactive contexts, keeps 60 seconds of exact history and a 300,000-event browser ring, and offers 10/30/60-second views. JSONL recording is independent of display/acquisition, and offline replay is incremental and bounded with pause, speed, progress, and restart.
- MCP stdio reserves stdout for JSON-RPC. Ordinary Python output is redirected to stderr only for the MCP entry; CLI, Web, and desktop logging remain unchanged.
