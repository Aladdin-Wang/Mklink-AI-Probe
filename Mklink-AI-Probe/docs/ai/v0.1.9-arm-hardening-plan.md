# MKLink 0.1.9 Arm 主线改造与回归计划

> 本计划覆盖官方用户手册、V3/V4 下载器固件、MKLink 0.1.9 上位机、AI Skill、MCP、WebGUI、
> 安装升级和 Arm 真机回归。HPM 系列另立专项，本轮只保证共享路径不退化。

## 1. 目标与成功定义

0.1.9 的目标不是继续堆入口，而是让同一项 Arm 能力在四个层面一致：

1. 固件真实实现和资源边界明确；
2. SDK、CLI、MCP、FastAPI 和 GUI 使用同一个业务与校验契约；
3. 官方手册给普通用户完整、可执行、可恢复的步骤；
4. 自动测试、真实浏览器和 V3/V4 真机能够重复证明结果。

发布候选必须满足：

- 公开功能均能追溯到实现、支持型号、最低版本、测试 ID 和最近真机证据；
- 非法输入、并发占用、超时、拔插和目标掉电不能让探针永久 busy 或必须重刷固件；
- 手册没有危险顺序、失效示例、绝对化宣传或维护流程泄漏到普通用户路径；
- 0.1.7/0.1.8 到 0.1.9 的真实安装升级完成闭环；
- 所有发布产物由同一个干净 commit 构建，并有版本、hash 和回归报告。

## 3. 已确认基线

### 3.1 官方手册

- `docs/tools/microlink` 共 28 页；用户教程、内部 API、协议、营销文章和维护流程混杂。
- `mkdocs build --strict` 被 3 个失效 HPM 链接阻断，另有 1 个失效售后图片路径。
- 5 个页面不在导航，其中包含旧 API、旧 MTP 和营销文章。
- `serial-modbus.md`、`questions.md`、`firmware-upgrade.md` 远不足以覆盖当前产品。
- `python_api.md` 同时承载用户 API、PC/AI 边界、协议帧和历史复测数据，必须分层。

### 3.2 固件

- V3/V4 共有 CMSIS-DAP、GPIO SWD、FLM/BIN/HEX、MSC、Python Console、UART、RTT、SystemView、
  VOFA/SuperWatch 和 `dump_memory`。
- V3 使用 SPI NOR；V4 使用 SD，并增加 RS485、LCD/编码器、本机界面和自动 VREF 跟随。
- Modbus 是上位机基于 UART/RS485 的协议能力，不是固件内建 Modbus 栈。
- `dump_memory` v1 有 CRC 和分块，但没有版本、frame type、sequence 和真实 telemetry。
- 当前固件依靠状态字段避让 SWD 使用者，没有原子 transport owner。

### 3.3 上位机

- 当前收集到 1479 个 Python 测试用例；GUI 有 55 个测试文件，最近完整运行 590 项通过。
- 在线/离线烧录、固件更新、流解析和 GUI 组件的单元测试较强。
- CLI、约 55 个 MCP 工具、公共 SDK、真实浏览器 E2E、clean-room 安装和破坏性 HIL 的系统覆盖不足。
- `mklink serve` 可在无 token 时绑定非回环地址且 CORS 过宽，是发布前安全阻断项。
- 正式签名安装包和真实 0.1.7/0.1.8 升级尚未验收。

### 3.4 真机夹具

- F103 Keil AXF 中已有连续 16 路变量，地址 `0x20009278..0x200092B4`。
- 工程根目录旧 `rt-thread.elf` 已删除；唯一符号源固定为
  `build\keil\Obj\rt-thread.axf`。
- F103 无 D-Cache，负责通用 Arm 功能和 16 路传输压力；H743 保留 cacheable/non-cacheable 对照。

## 4. 单一事实来源

先建立机器可读的 `probe-capabilities` 数据，再让代码和文档消费或校验它。每项能力至少包含：

```text
id
display_name
probe_models
minimum_firmware
host_surfaces
probe_entry
protocol_version
limits
exclusive_resources
risk_level
automated_tests
hil_tests
last_verified
```

建议落点：

- `_maintainer/firmware/probe-capabilities.json`：机器可读事实源；
- `docs/ai/probe-firmware-contract.md`：维护者可读说明；
- `_maintainer/testing/tests/test_probe_capabilities.py`：校验主机常量、MCP schema、GUI 型号选项和 Skill 边界；
- MicroBoot 手册中的功能矩阵由脚本生成，或在 CI 中与事实源逐项比对。

0.1.9 先记录当前能力并建立防漂移测试，不在没有 capability 协商的情况下修改现有线格式。

## 5. 实施批次

### 批次 A：契约和可重复基线

#### 工作

1. 建立上述 capability 数据和跨仓功能矩阵。
2. 冻结 `dump_memory` 当前格式为 `dump-v1`，补齐普通帧、分块帧、CRC、flags、停止和快速采样定义。
3. 提取 V3/V4 `.pyi`、C 绑定、USB descriptor、PC CLI、MCP schema 和 GUI 路由，生成差异报告。
4. 给 F103 HIL 夹具增加版本化 manifest：目标、构建 ID、AXF/BIN SHA-256、编译器和测试能力。
5. 所有 HIL 在开始前读取目标中的 build-id，并与 manifest/AXF 匹配；不自动搜索其他 ELF/AXF。

#### 验收

- 每个公开 Arm 功能有唯一 ID、型号、边界和测试 ID。
- V3/V4、主机和手册的已知差异全部可见；未验证项标记为 `unverified`，不推断支持。
- 同源 AXF/BIN 校验失败时，HIL 和 WebGUI 明确拒绝继续。

### 批次 B：P0 安全与恢复能力

#### 官方手册

1. Option Bytes 页面把料号确认、备份、RDP 解除会擦除 Flash、恢复路径放在第一条命令之前。
2. 删除“目标已有外部供电仍可并联下载器 VCC”的建议；按型号区分 VREF 输入和 VCC 输出。
3. 修正 `cmd.set_reset()`、`cmd.read_cpu_reg()` 的真实语义。
4. 下线或归档含循环外 `break`、错误 RTT 地址宏和旧 FLM 流程的文章。
5. 修复站点链接、图片、H1 和导航；首先达到 `mkdocs build --strict` 零警告。

#### V3/V4 固件

1. typed VOFA 读取长度使用实际 `type_size`，覆盖 i8/u8/i16/u16/i32/u32/float/double/bool。
2. 为 SWD 使用者增加统一 `debug_transport_owner`、busy ACK、取消、cleanup 和缓存失效。
3. Pika API 使用统一参数计数/类型/范围检查和单出口 cleanup；修复 V3 空文件指针关闭。
4. 未完成的 RBL 拖放升级明确返回 unsupported，不再静默进入空路径。
5. 任何失败后执行一个合法 `get_version`/memory smoke，证明 Console、owner 和状态已恢复。

#### 上位机

1. `mklink serve` 默认仅回环；非回环强制 `--allow-lan` 和 token；统一 CORS、REST、WS、二进制流认证。
2. token 不进入命令行、URL 或日志，只从环境变量或 owner-only secret file 读取。
3. `read_memory_regions` 保持 16/4096 B；连续 `dump_memory` 保持 15 region，并在发送前拒绝 16。
4. 禁止任何 SuperWatch 路径回退到循环 `read_ram`。
5. 统一 stream stop，淘汰仍发 `RTTView.stop()` 的旧 `read_dump_memory_once()` 行为。

#### 验收

- 非法、超限和并发命令不会让探针死机或永久 busy。
- LAN 无 token 绑定、任意 CORS、16-region 连续流均由自动测试拒绝。
- 所有高风险手册页面先说明风险和恢复，再出现命令。

### 批次 C：固件可靠性与可观测性

#### 工作

1. RTT/SystemView 使用固定上限数组，校验 Control Block 数量、channel、扫描范围和整数溢出。
2. 修复 SystemView 未初始化返回值，保证 start/stop 100 次后 Console 恢复。
3. UART/RS485 校验 baud、data bits、parity、stop bits 和实际误差；增加 RX/TX overflow、USB backpressure 计数。
4. ISR 只维护 DMA/SPSC 索引，消息分发移到线程；UART/Pika/YMODEM 使用明确 owner。
5. 限制 Pika serial read length；修复 YMODEM 文件数、字符串、malloc cleanup；receive 未实现前保持禁用。
6. 给 SD/NOR 增加介质 owner，MSC 主机写入期间固件 FATFS 不并发访问。
7. 在 transport owner 生命周期内再引入 DP SELECT/AP CSW/TAR 缓存和 scatter/gather SWD 读取。
8. 将 WAIT、FAULT、parity、retry exhaustion 分开统计，避免把 `MAX_SWD_RETRY=200` 当作所有错误的盲重试。

#### 验收

- telemetry 能区分目标更新、SWD 等待、固件丢样、USB backpressure、主机解析和前端 gap。
- owner 切换、reset、拔插、目标掉电和错误 FLM 后无需重刷下载器即可恢复。
- V3/V4 公共测试行为一致，型号特有功能有显式 capability。

### 批次 D：0.1.9 上位机架构和产品契约

#### 工作

1. 增加统一版本模块，基于 `importlib.metadata` 向 SDK、Agent、API、GUI 和发布脚本提供同一版本。
2. 统一最低 Python 版本；若仍支持 3.9/3.10，声明 `tomli` 条件依赖。
3. 删除 `python -m mklink` 运行时自动 editable install 和写 site-packages `.pth` 的行为。
4. 明确 wheel/sdist 是否为正式产品：若支持，补齐 `gui/dist`、RTT/SystemView 源和模板资源并使用
   `importlib.resources`；若不支持，在用户手册明确只支持安装包和 Skill ZIP。
5. 将 CLI、MCP、FastAPI router 和 GUI 后端收敛到共享 service/validator，先从 memory、stream、probe control 开始。
6. 为 CLI 二级命令、全部 MCP 工具、OpenAPI、资源租约和异常码建立 snapshot/contract tests。
7. 明确旧 JSON WebSocket、REST/SSE 和二进制 WebSocket 的主路径与淘汰计划。
8. 更新项目记忆校验，使其能检测记录的 HEAD 与实际 Git HEAD 漂移。

#### 验收

- 所有入口对同一请求给出一致限制、确认要求、错误码和资源 owner。
- clean-room Skill/安装包不依赖源码 checkout、editable install、Node 或 Rust。
- API、Agent、GUI 和日志报告的版本完全一致。

### 批次 G：Arm HIL 和浏览器闭环

#### F103 16 路主夹具

布局：

1. 16 个连续 `float`/`uint32_t`；
2. 16 个离散变量，覆盖 15-region 连续流与 16-region 快照；
3. 混合 i8/u8/i16/u16/i32/u32/float/bool；
4. 安全 scratch section、canary、build-id 和恢复值。

档位：1 kHz、5 kHz、10 kHz、20 kHz 请求和 fast。20 kHz 超过物理能力时不要求达到请求值，但必须稳定、
不损坏协议、不死机，并准确报告实际速率。

每档记录固件 flags/counters、frame/block CRC、parser、hub、WebSocket、Worker 和渲染 gap，以及周期
mean/p50/p95/p99。短测 5 分钟，候选 30 分钟；start/stop 和 period/config 切换各 100 次，固件稳定后再扩至
1000 次压力。

通用功能：

- CMSIS-DAP connect-under-reset、erase/program/verify/reset/run；
- BIN/HEX/FLM、错误算法、错误地址、取消和拔线恢复；
- RAM 非零/全零写回恢复、16/17 快照边界、core register、HardFault；
- RTT 上下行/ANSI/回绕、SystemView start/stop/overflow；
- V3/V4 脱机真实部署和触发；
- UART 自定义波特率，V4 RS485 与 Modbus RTU 回环；
- reboot/replug、目标掉电和 GUI 强制关闭后的恢复。

#### H743 缓存专项

- AXI SRAM cacheable 与 non-cacheable 对照；
- dirty D-Cache 和显式 clean；
- DTCM、跨 bank、ISR/线程更新；
- 重复 16 路启停、周期和丢帧指标。

F103 的通过结果不能替代 H743 缓存结论。

#### 真实 Chrome/Tauri

- MIME/旧缓存导致 18% 卡住；
- 当前 AXF、旧 AXF 隔离和 build-id 拒绝；
- SuperWatch 16 路启动、暂停、停止、缩放、滚动、历史、导出；
- 页面隐藏、刷新、关闭、崩溃后的 lease 回收；
- 丢帧链路诊断同屏显示；
- 在线/离线烧录、串口自定义波特率和真实错误；
- Tauri sidecar 启停、单实例和无残留进程。
